# План: бесплатные функции 2.x

## 1. Внешние отчёты и обработки по списку баз (issue #91, п.3)

**Цель.** Загрузить один или несколько файлов .erf/.epf в справочник
«Дополнительные отчёты и обработки» (БСП) сразу в отмеченные базы.

**Где в UI.** «Утилиты» → «Операции» → «Внешние отчёты и обработки…» и пункт
контекстного меню при мультивыделении «Для выделенных (N)» → «Загрузить обработки…».
Окно по образцу «Расширения конфигурации…»: список файлов (добавить/удалить),
список баз с галочками, режим «обновить существующую / только добавить новые»,
журнал выполнения.

**Как.** COM-соединение через `ComScriptRunner` (как «Пользователи ИБ» и «Регламентные
задания»). Тело операции PowerShell:

1. Файл передаётся в базу двоичными данными: `ПоместитьВоВременноеХранилище(Новый ДвоичныеДанные(путь))`
   через COM (`$c.NewObject("BinaryData", path)`, `$c.PutToTempStorage(...)`).
2. Сведения о внешней обработке: `ДополнительныеОтчетыИОбработки.ПолучитьРегистрационныеДанные`
   — в разных версиях БСП API отличается, поэтому порядок попыток:
   `ДополнительныеОтчетыИОбработкиВызовСервера` → «ручной» путь: создать объект
   через `ВнешниеОбработки.Создать(адрес, Ложь)` и прочитать `СведенияОВнешнейОбработке()`.
3. Поиск существующего элемента по `ИмяОбъекта` + `Вид`; если есть и режим «обновить» —
   заменить `ХранилищеОбработки`, `Версия`, `Информация`; иначе создать новый с
   `Публикация = Используется`.
4. Команды и разделы (`Назначение`, `Разделы`) заполняются из регистрационных данных;
   если что-то не удалось — элемент создаётся, а в журнал пишется предупреждение.

Новые файлы: `Services/ExternalProcessingsService.cs` (чистая логика: разбор результата,
валидация файлов, построение параметров), `ViewModels/ExternalProcessingsViewModel.cs`,
`Views/ExternalProcessingsWindow.cs` + `.Avalonia.cs`, пункт каталога
`UtilitiesMenuCommandKind.ExternalProcessings`, задание по расписанию
`ScheduledTaskKind.LoadExternalProcessings` (раскатывать обновлённую папку обработок ночью).

**Платформы.** COM есть только в Windows. На Linux пункт показывается с подсказкой
«нужен Windows» (как у «Пользователей ИБ»). Вариант для Linux на потом: загрузка
через служебную обработку с ключом `/Execute` в режиме Предприятия.

**Тесты.** Разбор JSON-результата (создан / обновлён / ошибка / нет БСП), валидация
расширений файлов, построение параметров, повторный запуск (идемпотентность).

**Риски.** Нет БСП или старая версия БСП — отдельный код ошибки `no_bsp` и понятный
текст. Безопасный режим обработок: в БСП 3.1+ при загрузке нужен флаг
`БезопасныйРежим` — по умолчанию оставляем как в регистрационных данных.

## 2. Значок «Предприятие» при отладке из Конфигуратора (issue #103)

**Проблема.** При запуске отладки (F5) Конфигуратор стартует `1cv8c.exe`/`1cv8.exe`
с командной строкой без `/F` или `/S` базы (подключение передаётся через
`/IBConnectionString`, `/DEBUG -http/-tcp`, иногда `/DisableStartupMessages` и `/O`),
поэтому `RunningInfobaseMatcher.MatchesCommandLine` её не узнаёт.

**Решение.**
1. `RunningInfobaseMatcher`: дополнительно разбирать `/IBConnectionString "File=...;"`
   и `"Srvr=...;Ref=...;"` (переиспользовать `OneCLaunchArgumentParser`).
2. Если строка процесса не содержит базы, а у процесса есть родитель — процесс
   конфигуратора (`1cv8.exe … DESIGNER`), то считать процесс «Предприятием» базы
   родителя. Родитель: Windows — `Win32_Process.ParentProcessId` (уже есть WMI-опрос
   в `RunningInfobasesService.Windows`), Linux — `/proc/<pid>/stat`, поле 4.
3. `RunningKind` для такого процесса — `Enterprise` (значок предприятия рядом
   со значком конфигуратора).

**Тесты.** `RunningInfobaseMatcherTests`: командные строки отладки (файловая и
серверная база, http/tcp-отладка), связь через родителя на синтетическом списке процессов.

## 3. Быстрый доступ к серверам по RDP и SSH

**Где в UI.** «Серверы 1С»: в карточке сервера (`ServerEditWindow`) новые поля «Адрес
для RDP» (по умолчанию — адрес сервера), «Пользователь RDP», «SSH: пользователь@адрес,
порт»; на панели монитора серверов — кнопки «RDP» и «SSH»; в трее — подменю «Серверы».

**Как.**
- Windows RDP: `mstsc /v:<host>[:port]`; учётные данные — через `cmdkey
  /generic:TERMSRV/<host> /user:<u> /pass:<p>` перед запуском (по желанию,
  флаг «Сохранить пароль в диспетчере учётных данных Windows»).
- Linux RDP: `xfreerdp /v:<host> /u:<u>` или `remmina -c rdp://u@host` (что найдено в PATH).
- SSH: Windows — `wt.exe ssh user@host -p port` (если есть Windows Terminal), иначе
  `cmd /c start ssh …`; Linux — терминал по умолчанию (`x-terminal-emulator`,
  `gnome-terminal --`, `konsole -e`) + `ssh`.
- Пароли хранятся так же, как прочие секреты серверов (через `NoteCrypto`/DPAPI),
  в командную строку пароль не попадает.

Новые файлы: `Services/RemoteAccessLauncher.cs` (построение команд — чистая логика,
`#if WINDOWS` для запуска), поля в `ManagementServer`, тесты построения команд.
