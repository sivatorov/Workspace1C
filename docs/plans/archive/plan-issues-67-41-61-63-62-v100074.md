## 1. Issue #67 — «Подстановки для сценариев»  ·  **объём L**

### 1.1. Контекст и корень проблемы (по коду 1.0.0.73)

1. **Производительность.** [`ScriptLaunchContextResolver.ResolveCore`](Workspace1C/Services/ScriptLaunchContext.cs:47) вызывает `OneCPlatformLocator.ResolveBinDirectory(infobase)` → `PlatformVersionService.FindPlatformVersionDirs(archKey)` — перечисление каталогов установленных платформ на ФС. Резолвер вызывается:
   - в живом превью [`ScriptScenarioEditViewModel.BuildExampleCommandLine`](Workspace1C/ViewModels/ScriptScenarioEditViewModel.cs:190) — **на каждое нажатие клавиши** в поле «Параметры» (тормоза «нажал пробел — 2–3 секунды», «первый вход в редактор — ~25 секунд»);
   - при построении диалога [`ScriptTokenPickerViewModel.BuildOptions`](Workspace1C/ViewModels/ScriptTokenPickerViewModel.cs:127) (строка 132, один раз на открытие);
   - при каждом запуске сценария [`MainViewModel.Scripts.cs:88`](Workspace1C/ViewModels/MainViewModel.Scripts.cs:88)/`.Avalonia.Scripts.cs` (разовый — не критично).
2. **Полнота структуры.** Карта [`BuildValueMap`](Workspace1C/Services/ScriptParameterResolver.cs:92) = явные ключи + рефлексия по СКАЛЯРНЫМ публичным свойствам `Infobase`/`ConnectionSettings`. Часть полей «структуры базы» (нескалярные/вложенные, `AdditionalFields`, производные) в карту не попадает, в диалоге «Выбрать…» у динамических ключей нет человекочитаемых описаний и группировки — пользователь воспринимает список как «не все поля структуры» и «просто добавление 5 полей».
3. **Корректность платформы.** `%full_exe_name%` для базы с 8.3.3 вернул `C:\Program Files\1cv8\8.5.4.1878\bin\1cv8.exe`. Причина-кандидат: точная версия базы не сопоставилась с установленной (несовпадение строки `PlatformVersion` базы с каталогами версий, см. `ResolveBinDirectory` [`OneCPlatformLocator.cs:21`](Workspace1C/Services/OneCPlatformLocator.cs:21) — fallback на «новейшую установленную»), И/ИЛИ платформы, установленные вне стандартных корней (не на диске C), не обнаруживаются `FindPlatformVersionDirs` — «вроде бы уже делали, чтобы везде одинаково определяло».
4. **«База для примера».** Окна редактора/выбора инициализируют комбобокс первой базой: [`ScriptScenarioEditWindow.xaml.cs:106-107`](Workspace1C/Views/ScriptScenarioEditWindow.xaml.cs:106), `.Avalonia.cs:336-337`; выделенная база, из которой вызван сценарий, не передаётся в окна.

## 4. Issue #63 — «Доработка публикации баз»  ·  **объём M**

### 4.1. Контекст и корень проблемы

В 1.0.0.73 `ParseDefines`/`ExpandVariables` раскрывают `${VAR}` **в пределах одного текста конфига** ([`ApacheConfIncludeParser.cs`](Workspace1C/Services/ApacheConfIncludeParser.cs:78)). У пользователя `Define SRVROOT`/`Define OneCPort` объявлены в главном конфиге, а `DocumentRoot`/`Listen` — во включаемых (`Include`) файлах: парсер include-файла не видит Define главного конфига → каталог публикации с литералом `${SRVROOT}` и пустой `ListenPorts` → «имя файла с переменной, но без значения», «подсказка после имени публикации — без порта». Требуется **двухпроходный разбор**: сначала собрать все `Define` по дереву Include, затем раскрыть.

### 4.2. Конкретные правки

1. **Двухпроходный парсер** ([`ApacheConfIncludeParser.cs`](Workspace1C/Services/ApacheConfIncludeParser.cs)):
   - новый метод `public static IReadOnlyDictionary<string, string> MergeDefines(IReadOnlyCollection<string> confTexts)`: последовательные `ParseDefines` по каждому тексту, поздние переопределяют ранние (семантика Apache по порядку подключения);
   - `ParseIncludeTargets`/`ParseDocumentRoot`/`ParseListenPorts` уже принимают `defines` необязательным параметром — использовать глобальный словарь;
   - товарный сбор: `ApacheInstanceDetector.PopulateIncludes` ([`ApacheInstanceDetector.cs`](Workspace1C/Services/ApacheInstanceDetector.cs)) — прочитать основной conf + тексты include-целей (через инжектируемый `Func<string,string?> readFileText` для тестов; реальный — `File.ReadAllText`), собрать `MergeDefines`, затем повторный проход: `ParseIncludeTargets` (для полного дерева), `ParseDocumentRoot`, `ParseListenPorts` с глобальным словарём.
2. **Подсказка и URL** ([`WebPublishViewModel.cs:152`](Workspace1C/ViewModels/WebPublishViewModel.cs:152), [`WebPublishWindow.cs:39-42`](Workspace1C/Views/WebPublishWindow.cs:39)):
   - после исправления парсера `Url` (через `WebPublishService.LocalUrl(VirtualDirectory, ListenPort)` [`WebPublishService.cs:184`](Workspace1C/Services/WebPublishService.cs:184)) получит порт — проверить отображение рядом с «Именем публикации»; при необходимости добавить явную подсказку «URL: http://localhost:<порт>/<имя>» (ключ локализации `WebPublish.UrlHint`) у поля имени публикации;
   - `PhysicalDirectory` — раскрытый путь из `DocumentRoot` (проверка).
3. **Примеры конфигов пользователя**: запросить у пользователя пример httpd.conf + include (он предложил) — положить в `Workspace1C.Tests/Fixtures/Apache/` (основной + включаемый файлы с Define до Include) и использовать в регресс-тестах.
