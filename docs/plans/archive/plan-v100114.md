## 1. Доработки по открытым issues (приоритет 1)

### 1.1. Issue #94 — зависание закрытия окна Свойств на Linux (ПРИЧИНА НАЙДЕНА)

В комментариях 7OH прислал точный стек: `NullReferenceException` в
`Workspace1C/Views/ConnectionSettingsWindow.Avalonia.cs:1460` — лямбда шаблона
`<BuildIdTab>b__1` в [`FuncDataTemplate`](Workspace1C/Views/ConnectionSettingsWindow.Avalonia.cs:1450).

- Причина: при закрытии окна Avalonia переразбирает контейнеры
  (`ClearContainerForItemOverride` → `ContentPresenter.UpdateChild` → сборка шаблона),
  при этом делегат шаблона вызывается с `row == null`, а код строки 1460/1471 делает
  `row.Number.ToString()` / `row.Value` без проверки — NRE обрывает цепочку закрытия
  (окно «скрывается без закрытия», далее зависание кадра `ShowDialogSync`).
- Фикс: в шаблоне `additionalList.ItemTemplate` (строки 1450–1487) проверить
  `row is null` → вернуть пустой `Grid`/`TextBlock` без обращения к `row`.
- Проверить WPF-аналог [`Workspace1C/Views/ConnectionSettingsWindow.xaml.cs`] — там XAML-байндинги,
  NRE не должен воспроизводиться; убедиться, что не используется тот же паттерн code-built шаблона.
- Тест: юнит-тест, что делегат шаблона (вынесенный в static-фабрику, если потребуется) не бросает при null-row.
- Регресс-проверка: сценарий «Свойства → вкладка Идентификатор → Отмена» на Linux-сборке.

## 3. Новые функции (реалистичные для одной итерации, приоритет 3)

### 3.1. Автоподстановка учётных данных СУБД из rac для серверных баз (issue #92)

Боль 7OH: для массовой выгрузки ibcmd на серверных базах нужен профиль СУБД, а создавать
профиль на каждую базу «влом». Данные (DBMS, сервер, имя БД, пользователь) можно получить
через `rac infobase info` / свойства кластера — уже используются в мониторе серверов.

- Новый сервис `Services/ClusterInfobaseCredentialsResolver` (по образцу
  [`Workspace1C/Services/ClusterInfobaseCredentials.cs`]): при отсутствии профиля СУБД у
  серверной базы — запрос через rac (уже найденные кластеры/порты) и подстановка dbms/server/name/user
  (пароль rac не возвращает — брать из профиля/свойств базы либо запрашивать один раз на операцию).
- Встраивание: [`Workspace1C/ViewModels/BatchOperationsViewModel.cs`] (массовая выгрузка DT/CF
  issue #92) и мастер развёртывания ([`TestDeployViewModel`]) — опция «Взять данные СУБД из кластера (rac)».
- Тесты: резолвер с фейковым IRacClient (креды найдены/не найдены/нужен пароль).
- Ценность: высокая (разблокирует массовую выгрузку серверных баз); трудоёмкость: средняя.

### 3.2. Блокировки сеансов/регламентных заданий перед массовыми операциями (issues #92, #91 — aepkugesi)

Минимальная версия для одного релиза: чекбокс «Завершить сеансы и заблокировать базу
на время операции» в окне массовой выгрузки DT / загрузки CF:

- перед операцией: `rac session terminate` (все сеансы кроме текущего COM/rac-соединения),
  установка блокировки начала сеансов с текущим временем и кодом разрешения (вводимым в окне),
  отключение регламентных заданий;
- после операции: снятие блокировок, включение регламентных заданий;
- при ошибке на середине — гарантированное восстановление блокировок (finally).

- Сервис: расширение [`Workspace1C/Services/IInfobaseAdminService.cs`] (или rac-обёртка
  из монитора серверов) — методы `SetSessionsDenial`, `TerminateSessions`, `SetJobsEnabled`.
- Тесты: логика восстановления блокировок при исключении (фейковый rac).
- Ценность: высокая для регламента бэкапов; трудоёмкость: средняя/высокая. Если не
  помещается в итерацию — перенести в v100115 (первый кандидат на перенос).
