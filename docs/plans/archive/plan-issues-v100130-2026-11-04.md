## 1. Issue #83 — «Лицензии»: окно деталей лицензии — убрать распознанные поля

### 1.1 Факт по последнему комментарию

## 2. Issue #79 — «Развернуть тестовую копию»: автоподстановка СУБД игнорирует работающий «infobase info»

### 2.1 Факт по последнему комментарию

7OH (2026-11-03 16:40, после анонса v1.0.1.29) — сравнение:

- В консоли rac 8.5.4 команда
  `rac localhost:27545 infobase info --cluster=… --infobase=… --infobase-user=Администратор --infobase-pwd=123`
  **отдаёт все поля СУБД**: `dbms: MSSQLServer`, `db-server: localhost`, `db-name: Demo_8.3.27`, `db-user: sa`.
- В логе приложения при тех же условиях:
  `Свойства базы «Demo_8.3.27» из «infobase summary list»: dbms=«», db-server=«», db-name=«», db-user=«»`
  — и профиль СУБД «не найден».

Вывод: резолвер берёт свойства из «infobase summary list» (в rac 8.5.4 поля пустые) и либо не
вызывает «infobase info», либо вызывает его с неработающими кредами/в неверном порядке
(v1.0.1.21–v1.0.1.22 добавляли догрузку через «infobase info» в
[`Services/ClusterInfobaseCredentialsResolver.cs`](Workspace1C/Services/ClusterInfobaseCredentialsResolver.cs) —
ветки issue #92 у строк 272–273 и issue #79 у строк 689–743), но в мастере развёртывания эта
ветка не срабатывает. Из консоли та же команда с теми же кредами ИБ проходит — значит, в
приложении проблема в построении команды/кредов/последовательности, а не в платформе.

### 2.2 Изменения

1. [`Services/ClusterInfobaseCredentialsResolver.cs`](Workspace1C/Services/ClusterInfobaseCredentialsResolver.cs):
   - При пустых полях СУБД в «infobase summary list» гарантированно выполнять «infobase info»
     (с кредами ИБ из формы/резолва — как в консоли у пользователя: `--infobase-user`/`--infobase-pwd`)
     и парсить `dbms/db-server/db-name/db-user` из него
     ([`RacOutputParser`](Workspace1C/Services/RacOutputParser.cs) уже умеет разбирать блоки).
   - Проверить: не обрезается ли «infobase info» по таймауту/ошибке прав ДО передачи кред;
     сверить фактическую командную строку (журнал CM_RAC, маскирование паролей) с консольной.
     В логе пользователя видно «Профиль СУБД исходной базы не найден… пробуем получить данные
     СУБД из кластера rac…» и дальше только summary list — ветка «infobase info» либо не
     вызывается, либо её результат отбрасывается.
   - Если «infobase info» отвечает «Недостаточно прав» при валидных кредах — проверить порядок
     и формат аргументов для rac 8.5.4 (перебор форматов, как сделано для list-команд, issue #25).
2. [`Services/RacClient.cs`](Workspace1C/Services/RacClient.cs): при необходимости — аналогично
   list-командам, перебор форматов передачи `--cluster`/`--infobase` для «infobase info»
   (формат-фолбэк уже реализован для «infobase summary list», строки ~294–307).
3. Мастер развёртывания (ViewModel сценария тестовой копии + [`Models/TestDeployScenario.cs`](Workspace1C/Models/TestDeployScenario.cs)):
   после успешного резолва через «infobase info» — автоматическое заполнение блока
   «Данные СУБД источника» (v1.0.1.29) значениями из профиля, чтобы пользователю не пришлось
   вводить вручную.
4. **Тесты**: юнит-тест резолвера — «summary list» с пустыми полями СУБД + «infobase info» с
   блочным выводом (как в консоли 8.5.4) → профиль собран (dbms=MSSQLServer, сервер, имя БД,
   db-user); тест на вызов «infobase info» с кредами ИБ.

## 3. Issue #92 — массовая выгрузка DT/CF: три остаточных дефекта движка «Конфигуратор»

### 3.1 Факты по последнему комментарию

7OH (2026-11-03 16:46, после анонса v1.0.1.29) + приложенные логи:

1. **«Кнопка Остановить по прежнему ничего не даёт»** — фикс v1.0.1.29 (Kill entireProcessTree
   при отмене ожидания Designer-операции) не работает в реальном сценарии: процесс 1cv8
   продолжает работу, кнопка «Выполнить» после завершения прогона остаётся недоступной
   (окно не разблокируется), переоткрытие окна — единственный выход.
2. **«Начало сеанса с информационной базой запрещено»** — из логов видно цепочку:
   - опции «Перед операцией» включают блокировки: `rac infobase update --scheduled-jobs-deny=on --sessions-deny=on`;
   - затем запускается `1cv8.exe DESIGNER /S… /DumpIB…` — Конфигуратор обязан **войти** в базу,
     но вход запрещён `sessions-deny=on` → код возврата 1, ошибка «Начало сеанса с информационной
     базой запрещено»;
   - то же повторяется на второй базе; разблокировка после ошибки выполняется не полностью
     (в логе второй базы остаётся `--scheduled-jobs-deny=on --sessions-deny=off` — scheduled
     снят, а в первой снимались оба).
   Конфликт: блокировка начала сеансов несовместима с движком «Конфигуратор» (в отличие от ibcmd,
   который работает на уровне СУБД). При движке «Конфигуратор» опция «Блокировка начала сеансов»
   должна блокироваться/не применяться с пояснением в журнале.
3. **rac «session terminate» падает**: `rac … session terminate --cluster=… --session=… --infobase-user=Администратор --infobase-pwd=***`
   → `«Ошибка разбора параметра: --infobase-user=Администратор»`. При этом «infobase info» с теми
   же `--infobase-user/--infobase-pwd` в этой же rac проходит. Похоже, rac 8.5.4 для
   «session terminate» НЕ принимает креды ИБ в таком виде (или не принимает значение с
   кириллицей без кавычек/экранирования). Нужно: исследовать допустимые параметры
   «session terminate» в rac 8.5.4 (возможно, креды кластера `--cluster-user/--cluster-pwd`
   или отдельный формат), скорректировать [`Services/RacClient.cs`](Workspace1C/Services/RacClient.cs)
   (аргументы «session terminate», строки ~924+) и/или
   [`Services/BatchOpsPreparationService.cs`](Workspace1C/Services/BatchOpsPreparationService.cs).
   Также из лога видно, что из-за неуспешного terminate сеансы оставались активными, а база всё
   равно блокировалась — заказ операций стоит скорректировать (terminate не удался → не включать
   блокировки / предупреждать).

### 3.2 Изменения

1. **«Стоп» + разблокировка окна (движок Конфигуратор)**
   ([`Services/BatchOperationsService.cs`](Workspace1C/Services/BatchOperationsService.cs),
   окна [`Views/BatchOperationsWindow.xaml`](Workspace1C/Views/BatchOperationsWindow.xaml) +
   Avalonia-версия):
   - ревизия пути отмены: «Стоп» во время Designer-операции обязан гасить запущенный процесс
     1cv8 (tree-kill) и корректно завершать текущий шаг прогона; проверить, что фикс v1.0.1.29
     реально вызывается для движка «Конфигуратор» (возможно, процесс запускается вне ветки,
     где ставится токен отмены, или kill происходит по другому Process-объекту);
   - по завершении прогона (успех/ошибка/остановка) кнопка «Выполнить» и остальные элементы
     окна гарантированно разблокируются — покрыть тестом на состояние ViewModel после отмены
     и после ошибки.
2. **Конфликт блокировок с движком Конфигуратор**
   ([`Services/BatchOpsPreparationService.cs`](Workspace1C/Services/BatchOpsPreparationService.cs)):
   - при движке «Конфигуратор» опция «Блокировка начала сеансов» не применяется: в окне —
     отключение/скрытие галочки с подсказкой, в сервисе — защита (не вызывать
     `infobase update --sessions-deny=on`), в журнале — строка-пояснение;
   - «Завершить сеансы» и «Блокировка регламентных заданий» оставить (совместимы), но
     гарантировать снятие ВСЕХ установленных блокировок после операции даже при ошибке
     (в логе пользователя после ошибки осталась `--scheduled-jobs-deny=on`);
   - если «session terminate» не сработал — не включать блокировки и писать предупреждение
     (сеансы остались, монопольная выгрузка всё равно не пройдёт).
3. **«session terminate» и rac 8.5.4**
   ([`Services/RacClient.cs`](Workspace1C/Services/RacClient.cs),
   [`Services/BatchOpsPreparationService.cs`](Workspace1C/Services/BatchOpsPreparationService.cs)):
   - диагностика формата: проверить передачу кред ИБ в «session terminate» (полный перебор
     допустимых вариантов: без кредов, `--cluster-user/--cluster-pwd`, креды ИБ — по образцу
     формат-фолбэка list-команд issue #25); в журнал — фактическая команда с маскированием;
   - при ошибке разбора параметра — автоматический ретрай без «лишних» параметров и честное
     сообщение в журнале, если сеансы завершить не удалось.
4. **Тесты**: отмены прогона (состояние ViewModel/разблокировка, kill процесса — по образцу
   существующих тестов массовых операций), матрица «движок × опции Перед операцией»

### 3.3 Критерии приёмки

- «Стоп» в окне массовой выгрузки останавливает процесс Конфигуратора; после завершения/остановки
  прогона «Выполнить» снова доступен без переоткрытия окна.
