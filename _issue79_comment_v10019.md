Доработано в версии 1.0.1.9 (Windows и Linux) по последнему комментарию:

1. **Кнопка-дубль «Учётные данные ИБ для ibcmd…» внизу окна убрана** — она дублировала
   блок «Данные для выгрузки через ibcmd» и кнопку «Свойства исходной базы» вверху
   окна ([`TestDeployWindow.cs`](Workspace1C/Views/TestDeployWindow.cs),
   [`TestDeployWindow.Avalonia.cs`](Workspace1C/Views/TestDeployWindow.Avalonia.cs)).
2. **Вместо дублирующих профиль полей — кнопка «Подставить из профиля СУБД…»**
   (по аналогии с «Подставить из базы» для логина/пароля): заполняет поля СУБД формы
   (тип, сервер, база, пользователь, пароль) из профиля исходной базы окна «Резервные
   копии СУБД»; при отсутствии профиля — подсказка. Поля остаются редактируемыми
   вручную — «либо данные из профиля, либо вручную».
3. **Работа выполняется по значениям на форме**: поля СУБД передаются в ibcmd как
   переопределение параметров подключения
   ([`TestDeployService.cs`](Workspace1C/Services/TestDeployService.cs),
   [`IbcmdService.cs`](Workspace1C/Services/IbcmdService.cs)) — молчаливой подмены
   из сохранённого профиля больше нет.
4. **Разовый сценарий (без сохранённого постоянного профиля) проходит валидацию**:
   пред-валидация ([`TestDeployPlanner.cs`](Workspace1C/Services/TestDeployPlanner.cs))
   принимает либо сохранённый профиль СУБД, либо заполненные поля СУБД на форме —
   ошибка «заполните профиль» появляется только когда нет ни того, ни другого.

Кнопка «Профиль СУБД для ibcmd…» (окно «Резервные копии СУБД») и «Общая авторизация…»
внизу окна остались на месте.

профиля, валидация разового сценария).
