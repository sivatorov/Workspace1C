## 1. Issue #79-а — «Ошибка при открытии интерфейса» после v1.0.1.32

### 1.1 Факт по коду (корень найден при анализе)

- В v1.0.1.32 по раскладке 7OH поля мастера сгруппированы в строки через новый хелпер
  [`MakeFieldsRow`](Workspace1C/Views/TestDeployWindow.cs:829) — он добавляет каждое поле
  в `StackPanel` внутри `Grid` ([`TestDeployWindow.cs:829-842`](Workspace1C/Views/TestDeployWindow.cs:829),
  строка 837: `cell.Children.Add(fields[i].Field)`).
- `_refBox` («Имя базы на сервере») при этом добавлен в дерево ДВАЖДЫ:
  - строка 225–226: `_serverPanel.Children.Add(MakeFieldsRow(("TestDeploy.Server", _serverBox), ("TestDeploy.Ref", _refBox)))`;
  - строка 244: `_serverPanel.Children.Add(_refBox);` — повторно, осталось от прежней
    вертикальной раскладки.
- В WPF добавление уже подключённого элемента в другой контейнер бросает
  `InvalidOperationException: «Specified element is already the logical child of another
  element. Disconnect it first»` — прямо в `TestDeployWindow..ctor`. Это в точности
  повторяет прецедент из того же issue (v1.0.1.1: падение `ApplyModernStyles` на
  PasswordBox → «ошибка при открытии (а ведь покрыто тестами…)», исправлено в v1.0.1.4).
- Avalonia-версия ([`TestDeployWindow.Avalonia.cs:202-219`](Workspace1C/Views/TestDeployWindow.Avalonia.cs:202))
  дублирования НЕ имеет (`_refBox` только внутри `FieldsRow`) — падает только Windows,
  что согласуется с репортом 7OH (у него Windows-сборка).
- Диагностика: ZIP `diagnostics_20261104_150557.zip` в
  [комментарии 7OH](https://github.com/sivatorov/Workspace1C/issues/79#issuecomment-6630155164)
  — на этапе реализации скачать (`Invoke-WebRequest`), распаковать (`Expand-Archive`)
  и подтвердить стек в записи `[ERROR] Ошибка интерфейса` лога.

### 1.2 Изменения

1. **Фикс (1 строка)**: в [`TestDeployWindow.cs`](Workspace1C/Views/TestDeployWindow.cs)
   удалить строку 244 `_serverPanel.Children.Add(_refBox);` — поле остаётся только внутри
   строки `MakeFieldsRow` («Сервер 1С» + «Имя базы на сервере», раскладка 7OH п.2).
   Обработчик `_refBox.TextChanged` (строки 227–243) остаётся без изменений.
2. **Проверка реверансом**: убедиться, что ни одно другое поле не добавляется дважды —
   пройтись по конструктору [`TestDeployWindow.cs`](Workspace1C/Views/TestDeployWindow.cs)
   (все вызовы `MakeFieldsRow` против последующих `Children.Add`) и по
   [`TestDeployWindow.Avalonia.cs`](Workspace1C/Views/TestDeployWindow.Avalonia.cs)

## 2. Issue #79-б — «лишние» типы СУБД в ComboBox

### 2.1 Факт по коду

- Список [`TestDeployDbmsOption.Values`](Workspace1C/Models/TestDeployDbmsOption.cs:36):
  `MSSQLServer, PostgreSQL, IBMDB2, OracleDatabase, MySQL, MariaDB` — составлен в
  v1.0.1.32 «по образцу списков диалогов создания базы кластера + MySQL/MariaDB».
- 7OH (2026-11-04 14:08): «напомню про лишние типы СУБД… какие 1с понимает, а какие
  лишние» — обсуждалось в прежних тикетах. 1С:Предприятие 8 в качестве СУБД поддерживает
  только **Microsoft SQL Server, PostgreSQL, IBM Db2, Oracle Database**; MySQL и MariaDB
  поддерживаются 1С только как веб-серверы публикации, НЕ как СУБД информационных баз —
  ibcmd/кластер с ними работать не сможет. Это подтверждается и тем, что у 7OH в
  реальном выводе `rac infobase info` тип — `MSSQLServer`.
- MySQL/MariaDB используются ТОЛЬКО в [`TestDeployDbmsOption.cs`](Workspace1C/Models/TestDeployDbmsOption.cs)
  (проверено поиском по `*.cs`) — изменение изолированное. Локализационные ключи:
  `TestDeploy.DbmsMySql`, `TestDeploy.DbmsMariaDb` в
  [`ru.json:4281`](Workspace1C/Localization/Languages/ru.json:4281) / `en.json`.

### 2.2 Изменения

1. [`TestDeployDbmsOption.cs`](Workspace1C/Models/TestDeployDbmsOption.cs):
   - из `Values` (строки 36–44) убрать `"MySQL"` и `"MariaDB"` — оставить
     `MSSQLServer, PostgreSQL, IBMDB2, OracleDatabase`;
   - из `KeyFor` (строки 85–94) убрать ветки `"MySQL"`/`"MariaDB"` (неизвестные значения
     всё равно отображаются «как есть»);
   - поправить doc-комментарий класса (перечень и обоснование: типы, реально
     поддерживаемые 1С для ИБ).
2. **Сохранение неизвестных значений НЕ трогать**: `BuildOptions(currentValue, …)`
   ([`TestDeployDbmsOption.cs:55-70`](Workspace1C/Models/TestDeployDbmsOption.cs:55)) —
   значение из rac/профиля, отсутствующее в списке, по-прежнему добавляется последней
   опцией (не терять ввод) — это осознанное поведение v1.0.1.32.
3. Локализация: удалить ключи `TestDeploy.DbmsMySql` и `TestDeploy.DbmsMariaDb` из
   `ru.json`/`en.json` (если нигде более не используются — проверить поиском по JSON).
4. **Консистентность ручного блока**: в Avalonia ручной блок «Данные СУБД источника»
   имеет список только из двух значений
   ([`TestDeployWindow.Avalonia.cs:329`](Workspace1C/Views/TestDeployWindow.Avalonia.cs:329):
   `MSSQLServer, PostgreSQL`) — привести к тем же четырём типам
   (`MSSQLServer, PostgreSQL, IBMDB2, OracleDatabase`); проверить WPF-вариант
   `_sourceDbmsCombo` ([`TestDeployWindow.cs:394+`](Workspace1C/Views/TestDeployWindow.cs:394))
   на тот же состав. Это закрывает и разнобой между платформами.
5. **Тесты**: обновить тесты ComboBox СУБД v1.0.1.32 (в `Workspace1C.Tests`): состав
   `Values` — ровно 4 поддерживаемых типа; неизвестное значение сохраняется; раскладка
   `IndexOf` не менялась.

**Файлы**: `Workspace1C/Models/TestDeployDbmsOption.cs`,
`Workspace1C/Views/TestDeployWindow.Avalonia.cs`, `Workspace1C/Views/TestDeployWindow.cs`
(если правится `_sourceDbmsCombo`), `Workspace1C/Localization/Languages/ru.json`,
`Workspace1C/Localization/Languages/en.json`, тесты `Workspace1C.Tests`.

### 2.3 Оценка

Сложность: **низкая**. Изменение изолировано одним классом + локализацией + списками
ручного блока.
