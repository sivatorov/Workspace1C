## [1.0.1.119] — 2026-11-25

### Добавлено

- **ПРО-витрина новых функций 2.x в меню (Windows и Linux).** Функции 2.x больше не
  скрываются без ключа: их пункты всегда видны в меню с отметкой « · ПРО» и подсказкой
  «требуется ключ». Клик по такому пункту без ключа открывает окно «Лицензия» и не
  выполняет действие; с ключом `major=1` в официальной сборке функции работают сразу
  после активации, без перезапуска.
  - группа «Сервисы» видна всегда: в официальной сборке — реальные пункты, в
    публичной — пункты «только в официальной сборке», которые не вызывают действие;
  - честные статусы в окне «Лицензия»: «доступна», «требуется ключ», «только в
    официальной сборке», «в разработке»;
  - новый пункт «Утилиты» → «Справка» → «Как купить ПРО…»;
  - в блоке «О программе» — ссылка на инструкцию «Как купить ПРО…»;
  - единый гейт для пунктов меню: окно «Лицензия» открывается один раз, двойного
    окна нет.

- **Инструкция по покупке и активации ПРО** — `docs/pro/HOW-TO-BUY-PRO.md`: где взять
  код компьютера, куда отправить, оплата 2000 ₽, выпуск ключа `--major 1`, активация,
  проверка, частые проблемы и что остаётся бесплатным.

### Изменено

- **ПРО: public core в 1.x остаётся бесплатным, новые 2.x-функции требуют ключ.**
  Публичное ядро (`ServerAlerts`, `TelegramBot`, `Mcp`, `ClusterMigration`, `TestDeploy`,
  `MassLoadCf`) в редакции 1.x доступно без ключа, как и раньше. Ключом закрываются
  **только новые функции 2.x** (`Pipelines`, `MultiBaseQuery`, `EnvironmentDiff`,
  `AutoTests`, `PerformanceTrends`, `AuditLog`, `CloudBackup`): для них нужен ключ
  `major=1` **и** официальная сборка с модулями ПРО (`PRO_MODULES`). Ключи `major=2` к
  версии 1.0.1.119 не подходят. Версии до 1.0.1.119 не переделываются.

- **Окна: единая политика адаптивных размеров (Windows и Linux).** Все модальные окна
  подчиняются одной политике: потолок **1200×800 DIP**, отступ от рабочей области
  монитора **48 DIP**, `MinWidth`/`MinHeight` не выше стартового размера, вертикальная
  прокрутка только когда содержимое выше окна. Стартовые размеры уменьшены (например,
  «Журнал регистрации» и «Расширения конфигурации» — 1100×720 вместо 1200×760 и 1180×760,
  «Пользователи информационных баз» — 1100×720 вместо 1240×820, «Регламентные задания
  информационных баз» — 1100×720 вместо 1280×800, «Серверы 1С» — 1200×680 вместо 1400×680).
  - на **1366×768@100 %** и **1920×1080@125 %** окно помещается целиком, нижние кнопки
    видны, вертикальной прокрутки нет;
  - на маленьких экранах (например, 1024×600) окно клампится по рабочей области и
    включает прокрутку, кнопки остаются вне зоны прокрутки;
  - изменения продублированы в WPF (Windows) и Avalonia (Linux), поведение совпадает;
  - горизонтальная прокрутка таблиц включается по необходимости, `MinWidth` колонок
    не менялся.

### Сборка

- Single-file сборки Windows (WPF) и Linux (Avalonia), версия **1.0.1.119**.
- Полный прогон тестов: число и результат фиксируются в T9 (база — **8043** теста,
  0 падений, 0 пропущено); в релизные документы попадает точное итоговое значение.

Собранные артефакты (single-file, self-contained, версия `1.0.1.119`):

| Платформа | Файл | Размер | Версия |
|---|---|---|---|
| Windows x64 (WPF) | `dist/win-x64/Workspace1C.exe` | фиксируется в T9 | `FileVersion` = `1.0.1.119` |
| Linux x64 (Avalonia) | `dist/linux-x64/Workspace1C` | фиксируется в T9 | `1.0.1.119` (в релизе — `Workspace1C-linux-x64`) |

Windows-бинарь собирается штатным `build-windows-single-file.ps1 -Configuration Release`;
smoke-проверка `Workspace1C.exe --list` (код 0, `stderr` пуст). Linux-бинарь —
кросс-сборкой `build-linux-single-file.ps1 -Configuration Release`
(`-p:ForceLinux=true`, linux-x64); запуск и smoke-тест Linux-бинаря выполняются
в CI на `ubuntu-latest` (этап релиза); локально на Windows Linux-рантайм недоступен.
