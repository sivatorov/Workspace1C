Здравствуйте, 7OH! Спасибо за точное описание сценария с запуском из трея.

Исправлено в версии **1.0.1.123** — [релиз v1.0.1.123](https://github.com/sivatorov/Workspace1C/releases/tag/v1.0.1.123).

**Причина.** В `OnStartup` окно входа показывалось **до** проверки одиночного экземпляра, поэтому новый процесс при повторном запуске ярлыком сначала запрашивал пароль и только потом обнаруживал уже работающий экземпляр.

**Что изменено:**

- проверка одиночного экземпляра и активация существующего окна выполняются **до** окна входа — в WPF (`App.xaml.cs`) и в Avalonia (`App.axaml.cs`);
- при уже работающем экземпляре новый процесс сигнализирует ему и завершается без окна входа; существующее окно активируется из трея без запроса пароля;
- команды `--register`/`--launch`/`--designer` обрабатываются как раньше — до гейта одиночного экземпляра;
- режим `AllowMultipleInstances` не затронут: при его включении запуск второго экземпляра и вход работают как прежде;
- при активной блокировке приложения пароль по-прежнему запрашивается.

Решение вынесено в чистую политику `StartupInstancePolicy` и покрыто тестами: `Issue164AccountPasswordPromptTests`.

**Что проверить на 1.0.1.123:**

- свернуть приложение в трей крестиком, затем запустить ярлык — существующее окно активируется без запроса пароля;
- при включённой блокировке приложения запуск ярлыком по-прежнему требует пароль;
- при `AllowMultipleInstances = true` запускается обычный второй экземпляр.

Issue не закрываю — прошу подтвердить на 1.0.1.123 и написать здесь.
