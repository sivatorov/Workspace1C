## 1. Issue #92 — окно «Выгрузить в DT\CF»: заголовок и кнопки после завершения

### 1.1 Факт по коду

- **Заголовок**: задаётся при создании окна тернарником по `kind`
  ([`BatchOperationsWindow.xaml.cs:121-125`](Workspace1C/Views/BatchOperationsWindow.xaml.cs:121):
  `DumpDt → "BatchOps.TitleDumpDt"`, `DumpCf → "BatchOps.TitleDumpCf"`, иначе `"BatchOps.TitleLoadCf"`;
  то же в [`BatchOperationsWindow.Avalonia.cs:88-92`](Workspace1C/Views/BatchOperationsWindow.Avalonia.cs:88)
  и при перестроении вида [`BatchOperationsWindow.Avalonia.cs:578-582`](Workspace1C/Views/BatchOperationsWindow.Avalonia.cs:578)).
  При смене вида операции DT↔CF на форме (изменение `vm.Kind` — обработка уже есть в окне:
  [`BatchOperationsWindow.xaml.cs:199-203`](Workspace1C/Views/BatchOperationsWindow.xaml.cs:199),
  [`BatchOperationsWindow.Avalonia.cs:757-761`](Workspace1C/Views/BatchOperationsWindow.Avalonia.cs:757))
  заголовок окна НЕ обновляется. Тексты ключей `BatchOps.TitleDumpDt`/`TitleDumpCf` в
  [`ru.json`](Workspace1C/Localization/Languages/ru.json) / `en.json` проверить: у пользователя
  отображается «Массовая выгрузка списка базы файлы .dt» — формулировку выправить и учесть оба вида.
- **Кнопки**: `IsRunning` сбрасывается в `finally`
  ([`BatchOperationsViewModel.cs:808-812`](Workspace1C/ViewModels/BatchOperationsViewModel.cs:808),
  комментарий «IsRunning сбрасывается ВСЕГДА»), но по отчёту 7OH после УСПЕШНОГО завершения
  (движок Конфигуратор) «Остановить» остаётся активной и бесполезной, «Выполнить» — неактивной.
  Кнопки обновляются только через `PropertyChanged(nameof(IsRunning))` в окнах — если уведомление
  пришло до финального сброса/потерялось/пришло из фонового потока без маршалинга, состояние кнопок
  залипает. Диагностика ZIP 7OH ([diagnostics_20261104_104757.zip](https://github.com/sivatorov/Workspace1C/issues/92#issuecomment-6625555940))
  — использовать как источник фактов.

### 1.2 Изменения

1. **Динамический заголовок** (обе платформы): в обработчике `PropertyChanged(Kind)` в окнах
   пересчитывать заголовок (`Title = T(...)` по текущему `Kind`); в Avalonia — и в перестроении
   вида. Выправить тексты `BatchOps.TitleDumpDt`/`TitleDumpCf` (ru: «Массовая выгрузка баз в файлы
   DT / CF» и т.п.; en аналогично), локализация ru/en.
2. **Состояние кнопок**: единый источник истины — `IsRunning` (+ наличие отмеченных баз для
   «Выполнить»). В `finally` после сброса `IsRunning = false` — явный `RaiseCanExecuteChanged`
   команд; в окнах после получения `PropertyChanged(IsRunning)` обновлять обе кнопки атомарно и
   гарантировать маршалинг на UI-поток ([`UiDispatch`](Workspace1C/Services/UiDispatch.cs)).
   Проверить ветку успешного завершения движка «Конфигуратор» ([`OneCLauncher.DesignerBatch.cs`](Workspace1C/Services/OneCLauncher.DesignerBatch.cs)):
   чтобы завершение процесса также завершало «зависшее» состояние Stop-флага VM (если отдельный
   флаг остановки — сбрасывать вместе с `IsRunning`).
3. **Тесты**: расширить [`Workspace1C.Tests/Issue92BatchDumpTests.cs`](Workspace1C.Tests/Issue92BatchDumpTests.cs):
   после успешного/ошибочного/отменённого прогона `IsRunning == false`, заголовок следует за `Kind`.

## 3. Issue #79 — «Развернуть тестовую копию»: данные СУБД источника из «infobase info»

### 3.1 Факт по коду и логам

- Лог 7OH (2026-11-03): `infobase info … — выполнено, exit=0, stdout=2673 симв.` — stdout НЕ пустой,
  данные в выводе есть (его ручной запуск rac показывает все поля: dbms=MSSQLServer, db-server,
  db-name, db-user). При этом профиль не собирается: в логе остаётся
  «Свойства базы … из "infobase summary list": dbms=«» …».
- В v1.0.1.30: перебор форматов `--cluster` в [`RacClient.GetInfobaseInfoAsync`](Workspace1C/Services/RacClient.cs:1032)
  и гарантированная догрузка в [`ClusterInfobaseCredentialsResolver.cs:264-310`](Workspace1C/Services/ClusterInfobaseCredentialsResolver.cs:264)
  (ToProfile из `RacInfobaseInfo`). Несмотря на это, 7OH на v1.0.1.30 (07:50) — «всё ещё пустые поля»
  + [diagnostics_20261104_104923.zip](https://github.com/sivatorov/Workspace1C/issues/79#issuecomment-6625598659).
- Гипотезы к проверке (по приоритету):
  1. **Парсер**: [`RacOutputParser.ToInfobaseInfo`](Workspace1C/Services/RacOutputParser.cs:762)
     возвращает объект с пустыми dbms/db-server/db-name/db-user при валидном выводе — несоответствие
     формата ключей/разделителей у rac 8.5.4 (например, разные виды пробелов/кодировка вывода).
  2. **Кодировка stdout**: ProcessRunner читает вывод в неверной кодировке (OEM-866/UTF-16) —
     ключи не совпадают, значения «пустые».
  3. **Пустой stdout у процесса**: rac.exe в ряде условий отдаёт вывод только в консоль/файл
     (вопрос 7OH «нужен ли вывод в файл этой команды?») — при stdout=0 и exit=0 нужен fallback.
  4. Резолвер после успешного `info` строит профиль НЕ из `info` (ветка ToProfile не достигается).

### 3.2 Изменения

1. **Диагностика**: в CM_RAC при «infobase info» логировать первые ~500 символов сырого stdout
   (или его длину + хэш-подпись первых строк) — чтобы по следующему ZIP сразу видеть, что реально
   возвращает rac; убедиться, что в ZIP-диагностике (Собрать диагностику) вывод команд тоже попадает.
2. **Парсер**: если ZIP подтвердит валидный вывод — починить [`RacOutputParser.ToInfobaseInfo`](Workspace1C/Services/RacOutputParser.cs:762)
   под фактический формат (устойчивость к разделителям/регистру/кодировке), тест на вывод, снятый
   с машины 7OH (дословно из его комментария/консоли).
3. **Fallback «вывод в файл»**: при exit=0 и пустом/нераспознаваемом stdout — повторный запуск rac
   через `cmd /c "rac.exe … > tmpfile"` (Windows) / shell-перенаправление (Linux) с чтением
   временного файла ([`ProcessRunner`](Workspace1C/Services/ProcessRunner.cs)); применять ТОЛЬКО
   к «infobase info» в резолвере (не менять общие list-команды). Удаление tmp-файла в finally.
4. **Проверка резолвера**: при непустом `info` профиль строится из `info` (не из summary) —
   добавить регрессионный тест в [`Workspace1C.Tests/ClusterInfobaseCredentialsResolverTests.cs`](Workspace1C.Tests/ClusterInfobaseCredentialsResolverTests.cs).
5. По итогам — прокомментировать issue с просьбой проверить в v1.0.1.31 (ZIP-диагностика при сбое).
