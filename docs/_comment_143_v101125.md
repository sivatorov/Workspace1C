Здравствуйте, RafaIS! Спасибо за проверку и уточнение — ошибка после ~3 минут ожидания воспроизведена и устранена.

Исправлено в версии **1.0.1.125** — [релиз v1.0.1.125](https://github.com/sivatorov/Workspace1C/releases/tag/v1.0.1.125).

**Причина.** В ожидании процесса `pg_dump`/`sqlcmd` оставался жёсткий таймер (около 3 минут): по его истечении копия прерывалась и показывалась ошибка, даже если утилита ещё штатно работала (большая база, медленный диск). Переключатель `CM_DEBUG_DBMS` существовал только как переменная окружения, поэтому в «Настройки → Логирование» его не было видно.

**Что изменено:**

- `TimeoutMinutes = 0` теперь означает «без ограничения» — ожидание процесса СУБД идёт без жёсткого таймера;
- в окне резервных копий появилось поле «Таймаут копии: мин (0 — без ограничения)»;
- отмена завершает процесс СУБД и удаляет недописанный файл резервной копии (не остаётся «битых» дампов);
- в «Настройки → Логирование» добавлен переключатель «Диагностика резервного копирования СУБД (CM_DEBUG_DBMS)»: значение сохраняется в настройках и включает запись журнала `dbms-backup-debug.log`;
- паритет WPF (Windows) и Avalonia (Linux); тесты `Issue143*`.

**Что проверить на 1.0.1.125:**

- поставить «Таймаут копии» = 0 и выполнить копию большой базы — операция не прерывается через ~3 минуты;
- задать явный таймаут в минутах — копия прерывается по нему с понятным сообщением;
- нажать «Отмена» во время копии — процесс СУБД завершается, недописанный файл удаляется;
- включить «Настройки → Логирование → Диагностика резервного копирования СУБД (CM_DEBUG_DBMS)», повторить сценарий — создаётся `dbms-backup-debug.log`, настройка сохраняется после перезапуска.

Issue не закрываю — прошу подтвердить на 1.0.1.125 и написать здесь.
