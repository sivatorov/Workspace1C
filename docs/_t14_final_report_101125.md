## 4. Проблемы и отклонения

### 4.1. Размеры/хэши ассетов релиза отличаются от подготовленной локальной сборки

- Подготовленные локальные артефакты (`dist/`, `_rel_101125/`, отчёт T11):
  - `Workspace1C.exe` — **85 708 123** байт, `sha256 d4c61f0545a3b809e0ae9a66cd9d3bdc05e6cc2ebe15aa7422689fe564bb1f92`;
  - `Workspace1C-linux-x64` — **53 996 012** байт, `sha256 1778902f4cf765829e907a71514d6ea3ac72a168697eadca0d5533615906ed14`.
- Фактические ассеты на GitHub (`gh release view v1.0.1.125`):
  - `Workspace1C.exe` — **85 599 766** байт, `sha256 8d627724f5b657e6dc799c9498a68fbd641b690d400c21b94b134235f72907fe`;
  - `Workspace1C-linux-x64` — **53 889 319** байт, `sha256 e518d9519b79d73e2364fbcfcc89be39178eec37d0f6c37714c24ddc2ac81590`.
- **Причина:** локальные артефакты собраны из рабочего дерева на базе коммита `603e1fa1`
  (`ProductVersion = 1.0.1.125+603e1fa1...`), а в релиз загружена **пересборка из коммита релиза
  `009e77e1`** (`ProductVersion = 1.0.1.125+009e77e13601e10351e50666a1614a7c82e42e65`). Пересборка
  дала побайтово другой, но функционально тот же файл.
- **Проверка корректности релиза:** скачанный из релиза `Workspace1C.exe` имеет
  `FileVersion = 1.0.1.125`, `ProductVersion = 1.0.1.125+009e77e13601e10351e50666a1614a7c82e42e65`,
  то есть релиз содержит **правильную версию 1.0.1.125**, собранную из целевого коммита релиза.
- **Вывод:** релиз корректен; расхождение — в числах отчёта T11 (они относятся к ранней локальной
  сборке). Пересоздание релиза/перезаливка ассетов **не выполнялись** (запрещено условиями задачи).
  Рекомендация: при следующем релизе фиксировать размеры/SHA именно загруженных ассетов.
