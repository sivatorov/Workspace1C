Что было не так (по коду):

1. Профиль `dbms_backups.json` читался прямо в конструкторе окна
   (`DbmsBackupService.Load()`), а конструктор вызывается из команды меню на
   UI-потоке. При старом/сетевом профиле окно могло «залипнуть» ещё до показа.
2. Проверка подключения вызывалась как `check(profile, CancellationToken.None)` —
   её синхронная часть (DNS, `TcpClient`, запуск `pg_isready`/`sqlcmd`) выполнялась
   на UI-потоке, а токен не передавался вовсе, поэтому таймаут не отменял работу.
3. Запись профиля (`FeatureDataStore.Save`) не принимала `CancellationToken`, а
   проверка каталога не проверяла отмену до/после файловых операций — недоступный
   UNC-каталог мог висеть.
4. Старые профили (`TimeoutMinutes = 0`, пути в кавычках/с пробелами, отрицательный
   `KeepCount`, неопределённый тип СУБД) не нормализовались и уходили в блокирующую
   операцию.

Что исправлено в **1.0.1.113** (Windows и Linux):

- профиль больше не читается в конструкторе: данные догружаются в фоне
  (`InitializeAsync`), а команда меню читает их в фоне **до** показа окна;
- `SaveAsync` пишет профиль через `Task.Run(SaveCore)` с `CancellationToken` и
  `WaitAsync`; `FeatureDataStore` получил асинхронные `LoadAsync`/`SaveAsync`
  (формат JSON не изменился);
- проверки подключения и каталога целиком выполняются в `Task.Run`; связанный
  `CancellationTokenSource` с `CancelAfter` и `WaitAsync` реально отменяет DNS,
  `TcpClient`, `pg_isready` и `sqlcmd`; каталог проверяет токен до/после каждой
  файловой операции;
- старые профили нормализуются без сетевых операций (`TimeoutMinutes = 0` → 360,
  пути без кавычек/пробелов, корректный `KeepCount`), а не молча зависают;
- окна используют только `async`-обработчики без `.Result`/`.Wait()`; по таймауту
  показывается понятное сообщение «Сохранение профиля не завершилось за 15 секунд»
  или «Превышено время ожидания проверки», кнопки снова активны, «Отмена» работает;
- тесты заменены на поведенческие: блокирующие заглушки, возврат по таймауту,
  сброс `IsBusy`, доставка отменённого токена, загрузка старого `dbms_backups.json`
  без исключения.
