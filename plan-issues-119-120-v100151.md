### 2.1. Issue #119 — «Кэш баз при удалении» (сложность: низкая, независимый)

**Ориентир:** описание issue (комментариев нет).

**Суть/запрос пользователя (aleksandr-ermakov):**
- Непонятно, что происходит с кэшем базы при её удалении из списка.
- Просит: показывать **размер кэша** в диалоге удаления и добавить **опцию «Удалить кэш»**
  (по аналогии с опцией удаления файлов базы, включена по умолчанию).
- Альтернатива, если кэш уже удаляется: явно написать об этом в диалоге удаления.

**Подход к исправлению:**
1. В диалоге удаления ([`DeleteInfobaseWindow.xaml`](Workspace1C/Views/DeleteInfobaseWindow.xaml) +
   [`DeleteInfobaseWindow.xaml.cs`](Workspace1C/Views/DeleteInfobaseWindow.xaml.cs) — WPF;
   [`DeleteInfobaseWindow.axaml`](Workspace1C/Views/DeleteInfobaseWindow.axaml) +
   [`DeleteInfobaseWindow.Avalonia.cs`](Workspace1C/Views/DeleteInfobaseWindow.Avalonia.cs) — Avalonia):
   - вычислить суммарный размер кэша базы через существующий junction-aware механизм
     ([`OneCCacheCleaner.cs`](Workspace1C/Services/OneCCacheCleaner.cs) — размер считается по
     цели ссылок, дополнительные корни из настроек учитывать, см. v1.0.1.39/40);
   - добавить чекбокс «Удалить кэш базы (N МБ)» — по умолчанию **включён**, доступен
     для файловых и серверных баз (у серверных кэш лежит локально у клиента);
   - для не-файловых баз панель физического удаления каталога прячется (как сейчас),
     а опция удаления кэша остаётся видимой.
2. При подтверждении удаления: если чекбокс отмечен — очистить каталоги кэша базы
   (в т.ч. junction-цели — содержимое, не саму ссылку), используя helpers
   [`OneCCacheCleaner.cs`](Workspace1C/Services/OneCCacheCleaner.cs); ошибки удаления кэша
   не блокируют удаление базы из списка — предупреждение в журнал/диалог.
3. Точки вызова удаления (общее окно используется и в массовом удалении):
   [`MainViewModel.Commands.cs`](Workspace1C/ViewModels/MainViewModel.Commands.cs:457),
   [`MainViewModel.Avalonia.Tools.cs`](Workspace1C/ViewModels/MainViewModel.Avalonia.Tools.cs:1086),
   [`MainViewModel.BatchCommands.cs`](Workspace1C/ViewModels/MainViewModel.BatchCommands.cs:177),
   [`MainViewModel.Avalonia.BatchCommands.cs`](Workspace1C/ViewModels/MainViewModel.Avalonia.BatchCommands.cs:175) —
   протянуть флаг «удалить кэш» из диалога в фактическое удаление.
4. Локализация ru/en — новые строки `DeleteInfobase.*` (размер кэша, подпись чекбокса,
   предупреждение о невозможности удалить кэш).

**Файлы для изменения:**
- [Workspace1C/Views/DeleteInfobaseWindow.xaml.cs](Workspace1C/Views/DeleteInfobaseWindow.xaml.cs),
  [Workspace1C/Views/DeleteInfobaseWindow.xaml](Workspace1C/Views/DeleteInfobaseWindow.xaml)
- [Workspace1C/Views/DeleteInfobaseWindow.Avalonia.cs](Workspace1C/Views/DeleteInfobaseWindow.Avalonia.cs),

- файлы локализации ru/en

**Тесты:** юнит-тесты на расчёт размера кэша и очистку (junction/symlink уже покрыты

### 2.2. Issue #120 — «Переход к открытому окну Конфигуратора/Предприятия» (сложность: средняя)

**Ориентир:** комментарии, не от sivatorov:
- RafaIS 2026-11-10 13:31:59 (последний): «логично переходить к открытому окну, запускать
  другое — редкость»;
- 7OH 13:05 / 13:07 / 13:22: у кого-то колонка действий скрыта, два Предприятия иногда
  нужны; для Конфигуратора — просто активировать окно запущенного; для Предприятия —
  спрашивать «новое окно или открыть запущенное (с выбором, если несколько)» не надо —
  7OH предлагает: переход по клику на значке-индикаторе.

**Итоговая постановка (консенсус обсуждения):**
1. **Конфигуратор**: двойной щелчок по базе и кнопка запуска Конфигуратора — если
   Конфигуратор этой базы уже запущен, **активировать его окно** (вывести на передний
   план) вместо запуска нового экземпляра.
2. **Предприятие**: кнопка запуска/двойной щелчок — запускать новый экземпляр как сейчас
   (несколько экземпляров легитимны); **клик по значку-индикатору «Предприятие»** в чипе
   базы — активировать окно запущенного Предприятия; если запущено несколько — показать
   выбор из списка окон (заголовки/PII), переход к выбранному.
3. Кнопка-«треугольник» (отдельный запуск новой сессии) — поведение без изменений
   (из описания issue RafaIS).

**Подход к исправлению:**

  см. [App.xaml.cs](Workspace1C/App.xaml.cs:762)) и [`OneCWindowActivator.Linux.cs`](Workspace1C/Services/OneCWindowActivator.Linux.cs).
- Данные о запущенных процессах базы уже собираются монитором
  ([`MainViewModel.Running.cs`](Workspace1C/ViewModels/MainViewModel.Running.cs:67) →
  `RunningInfobaseMatcher.MatchProcesses`, флаги `IsEnterpriseRunning`/`IsConfiguratorRunning`).
- План работ:
  1. Расширить [`OneCWindowActivator`](Workspace1C/Services/OneCWindowActivator.Windows.cs):
     метод «перечислить окна 1С, относящиеся к конкретной базе» (сопоставление по PID
     процессов базы от матчера, при необходимости — по заголовку окна) + метод
     «активировать окно по PID»; для варианта «несколько окон» вернуть список для выбора.
  2. В точке запуска ([`MainViewModel.Launch.cs`](Workspace1C/ViewModels/MainViewModel.Launch.cs:257),

  3. Клик по значку Предприятия в чипе: WPF — обработчик в шаблоне строки
