Здравствуйте, RafaIS! Спасибо за подробные проверки и точные замечания — по ним удалось довести сценарий до рабочего состояния.

Исправлено в версии **1.0.1.120** — [релиз v1.0.1.120](https://github.com/sivatorov/Workspace1C/releases/tag/v1.0.1.120).

**Причина.** Проверки подключения и каталога не покрывали наличие самой утилиты (`pg_dump`/`sqlcmd`) и аутентификацию, поэтому копия могла начаться и упасть уже после «успешных» проверок. Кроме того, при частичной записи файл копии удалялся, ротация с малым `KeepCount` могла удалить только что созданную копию, а сбой сохранения профиля отменял запуск копии.

**Что изменено:**

- подпись поля — «Каталог с программой pg_dump / sqlcmd» и подсказка «Укажите папку, где лежит утилита…» (больше не создаётся лишняя папка по умолчанию);
- ошибка теперь понятная: этап, путь, код возврата утилиты и последние строки `stderr` (пароли маскируются);
- свежая копия защищена от ротации — только что созданный файл не удаляется;
- копия продолжается, даже если сохранение профиля не удалось;
- окно немодальное: своя плашка на панели задач, фоновая задача, переключение обратно на стартер, отмена кнопкой «Отмена»;
- диагностика `CM_DEBUG_DBMS=1` (`dbms-backup-debug.log`) сохранена и дополнена.

Паритет WPF/Avalonia, локализация ru/en. Тесты: `Issue143NonModalAndCopyFixTests`, `Issue143DbmsBackupTests`, `Issue143ResponsivenessTests`, `Issue143UiHangDiagnosticsTests`.

**Что проверить на 1.0.1.120:**

- после успешных проверок копия создаётся, файл остаётся в каталоге;
- при ошибке сообщение содержит причину (путь, код возврата, `stderr`);
- окно не блокирует стартер и имеет свою плашку на панели задач;
- отмена копии кнопкой не подвешивает окно.

Если ошибка повторится — включите `CM_DEBUG_DBMS=1`, повторите сценарий и пришлите `dbms-backup-debug.log`.
