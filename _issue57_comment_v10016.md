Исправлено в версии **1.0.1.6** (Windows и Linux):

«Общая авторизация» теперь перекрывает авторизацию ОС базы. База с «выключенной насильственной авторизацией» (режим `Windows`, фактически `/WA+` без `/N`/`/P`) больше не блокирует общую авторизацию: явные общие учётные данные режима (`CommonEnterpriseAuthorization`/`CommonConfiguratorAuthorization`/legacy) подставляются в любом случае
([`InfobaseAuthResolver.Resolve`](Workspace1C/Services/InfobaseAuthResolver.cs)). Connection перекрывает общую только если задана режимом Credentials с пользователем (собственные учётные данные — высший приоритет) либо это режим ОС без заданных общих кредов.

Выполнен сквозной аудит всех мест использования пароля от базы (запуск Предприятия/Конфигуратора, пакетные команды конфигуратора, COM-подключение, ibcmd, пользователи ИБ, токены скриптов) — все пути входа в ИБ идут через единый резолвер; итог зафиксирован комментарием в коде. После резолва в журнал пишется режим и источник авторизации без пароля (CM_BASE_RUN) — следующий репорт диагностируем с первого сообщения.
