## [1.0.1.115] — 2026-11-24

### Исправлено

- **Окно «Резервные копии средствами СУБД» больше не зависает (issue #143,
  Windows и Linux).** Причина: сохранение шло через синхронный `SaveCore` с
  `GetAwaiter().GetResult()` — поток пула блокировался на файловой операции
  (в том числе на сетевом `%APPDATA%`), а таймауты `WaitAsync`/`CancelAfter`
  жили в том же пуле и не срабатывали; каждый повторный клик добавлял ещё один
  заблокированный поток.
  - `SaveCore` удалён, сохранение выполняется настоящим `await` — без
    `.Result`/`.Wait()`/`GetAwaiter().GetResult()` в пути UI;
  - новый `DbmsTimeoutGuard` считает таймаут на выделенном потоке
    (`TaskCreationOptions.LongRunning`) и не зависит от занятости пула;
    `BlockingIo` выносит файловые операции и запуск процессов на отдельный
    поток;
  - `IsBusy` выставляется до тяжёлых вызовов, повторный вход отсекается;
    исправлен бесконечный ре-пост в `AppendLog`;
  - диагностика `DbmsBackupTrace` (флаг `CM_DEBUG_DBMS=1`, файл
    `dbms-backup-debug.log` в каталоге журналов): этапы, идентификатор потока,
    путь профиля и тип пути, взвод и срабатывание таймаута;
  - новый `UiThreadWatchdog` (WPF и Avalonia) пишет WARN при паузе UI-потока
    более 3 с и указывает последний этап; по таймауту в журнал окна выводится
    этап и подсказка прислать `dbms-backup-debug.log`; новые ключи локализации
    `Dbms.TimeoutDetails`, `Dbms.SendDebugLog` в `ru.json` и `en.json`;
  - тесты `Issue143UiHangDiagnosticsTests`, обновлён
    `Issue143DbmsBackupTests`.

- **Окна правки структуры меню («Утилиты», «Меню трея», «Мои программы»)
  показывают пояснение без прокрутки (issue #146, Windows и Linux).**
  Причина: окна открывались с высотой 560 (580 для «Моих программ») и
  `MinHeight` 480/500, а поясняющий текст лежал внутри прокручиваемой панели
  (в «Моих программах» — во вложенных `ScrollViewer`), поэтому при масштабе
  100–150 % он уходил под нижнюю границу окна.
  - `DialogWorkAreaPolicy.Recommend()` задаёт новые высоты: 760 для редакторов
    меню и 780 для «Моих программ», `MinHeight` — 600; кламп по рабочей
    области сохранён;
  - пояснение вынесено из `ScrollViewer` в `DockPanel` с
    `DockPanel.Dock="Bottom"` — прокручивается только список операций;
  - в «Моих программах» убрана двойная вложенность прокрутки;
  - изменения продублированы в WPF и Avalonia-версиях окон, окна остаются
    resizable;
  - тесты `Issue146WindowHeightTests`, обновлён `Issue146DialogSizeTests`.

- **Кнопка «Обновить» снова открывает диалог после «Пропустить эту версию»
  (issue #155, Windows и Linux).** Причина: ручная проверка при пропущенном
  релизе делала ранний выход `SetAvailableRelease(null); return;`, поэтому
  диалог не показывался и кнопка выглядела нерабочей.
  - новая логика `UpdateManualCheckLogic` (`IsSkipped`/`Plan`) отделяет ручную
    проверку от фоновой: ручная всегда открывает диалог, фоновая по-прежнему
    скрывает пропущенный релиз;
  - новый `ClearSkippedVersion` сбрасывает пропуск при явном обновлении;
  - `GitHubReleaseService` сравнивает версии численно с нормализацией до
    4 частей, поэтому `1.0.1.9` больше не считается новее `1.0.1.10`;
  - в окне обновления показывается пояснение `Update.SkippedHint` (WPF и
    Avalonia), ключ добавлен в `ru.json` и `en.json`;
  - тесты `Issue155SkippedManualUpdateTests`, обновлены `Issue116*`.

- **Индикатор запуска у двух одинаковых записей базы выбирается
  детерминированно (issue #153, Windows и Linux).** Причина: ключ базы
  смешивал подключение и `Id`, дубликаты «схлопывались» через `HashSet`, а
  результат сопоставления хранился по ключу подключения — при полном совпадении
  настроек индикатор получали обе строки.
  - введены `GetConnectionKey` (группировка) и `GetRecordKey` (`Id`, иначе
    стабильный индекс записи в сохранённом профиле);
  - `OrderDeterministically` и `RecordIdentityComparer` задают полный порядок
    выбора владельца: явный пользователь → запись без явных учётных данных →
    ключ записи → индекс в сохранённом списке;
  - результат сопоставления хранится по ключу записи — индикатор получает
    ровно одна строка; расширена диагностика `RunningMatchDebug` (`recordKey`,
    `connectionKey`, индекс записи, выбранный владелец);
  - тесты `Issue153DeterministicOwnerTests`, обновлён
    `Issue153SharedConnectionTests`.
