Здравствуйте, 7OH! Спасибо за скриншот и описание — проблема с раскрывателем и иконками воспроизведена и исправлена.

Исправлено в версии **1.0.1.123** — [релиз v1.0.1.123](https://github.com/sivatorov/Workspace1C/releases/tag/v1.0.1.123).

**Причина.** Раскрыватель строился вращением одного глифа через `RenderTransform` и визуально «схлопывался в точку», а зона клика была узкой. Часть редакторов использовала PackIcon-ключи, которые резолвились в одну и ту же иконку папки. Окна правки имели фиксированную высоту с внешней прокруткой.

**Что изменено:**

- общая тема дерева использует два явных глифа — `IconChevronRight` (свёрнуто) и `IconChevronDown` (раскрыто) — без `RenderTransform`;
- зона клика раскрывателя — вся колонка 24×24 на высоту строки, поэтому попадать в «точку» не нужно;
- иконки узлов строятся по геометрическому ключу с единым фолбэком (`IconFolder`) во всех редакторах: «Утилиты», «Контекстное меню», «Меню в трее»;
- четыре окна правки открываются по содержимому (`SizeToContent = Height`), `MaxHeight` клампится по рабочей области через `DialogWorkAreaPolicy`, прокрутка остаётся только аварийным режимом.

Паритет WPF/Avalonia, локализация ru/en. Тесты: `Issue159UtilitiesContextMenuTests` и тесты политики размеров диалогов.

**Что проверить на 1.0.1.123:**

- раскрытие и сворачивание кликом по всей колонке раскрывателя, глиф не превращается в точку;
- иконки узлов различимы в «Контекстном меню» и «Меню в трее»;
- в четырёх окнах правки при нормальном разрешении нет постоянного скролла;
- на маленьком экране окна не выходят за рабочую область, прокрутка включается только при нехватке места.

Issue не закрываю — прошу подтвердить на 1.0.1.123 и написать здесь.
