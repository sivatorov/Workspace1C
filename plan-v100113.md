## 1. Доработки по открытым issues (приоритет 1)

### 1.1. Issue #83 — Лицензии сервера 1С (ring)

Проблема (7OH): утилита ring найдена в консоли, но в окне «Серверы 1С» — «не найдено»;
вкладку лицензий трудно заметить; при недоступности утилиты/модуля — пустая вкладка.

- [`Workspace1C/Views/ServerMonitorWindow.Avalonia.cs`] и WPF-аналог: переместить вкладку
  «Лицензии» ПЕРЕД вкладкой «Информация о кластере» (просьба 7OH из описания issue).
- [`Workspace1C/Services/RingLicenseService.cs`]: при недоступности утилиты вернуть в
  `RingLicenseResult.Warning` человекочитаемый текст (уже частично есть) и **гарантированно
  показывать его на вкладке Лицензии** (сейчас пусто при «не найдено») — в окнах
  монитора сервера вывести Warning-плашку `WarningBrush` вместо пустого списка.
- [`Workspace1C/Services/RingLicenseService.cs`], Windows-ветка: `where.exe ring` находит
  `ring.cmd` — после получения пути запускать **полный путь через cmd.exe /c** (или сам
  найденный путь), а не «ring» как есть: у процесса приложения PATH может отличаться от
  PATH консоли пользователя. Логировать resolved-путь в CM_RAC (частично сделано в 1.0.1.11).
- Тест: [`Workspace1C.Tests/`] — юнит-тест на разбор Warning → текст плашки.

### 1.2. Issue #79 — Мастер «Развернуть тестовую копию» (остатки UX)

Проблема (7OH, комменты 5–8): дублирующая кнопка «Учётные данные ИБ для ibcmd» внизу
открывает не то окно; поля формы дублируют профиль; обязательность профиля неочевидна.

  1) убрать нижнюю дублирующую кнопку «Учётные данные ИБ для ibcmd» (коммент 7, п.1);
  2) добавить кнопку «Из профиля» рядом с полями СУБД (хост/имя БД/логин/пароль) —

- [`Workspace1C/ViewModels/TestDeployViewModel.cs`]: методы `FillFromProfile()` и
  `EnsureIbcmdProfileFromForm()` + тесты в `Workspace1C.Tests/`.

### 1.3. Issue #89 — Автообновление на Linux (финальный шаг установки)

Проблема (7OH, коммент 4): ассет linux-x64 скачан корректно, но «Не удалось установить
обновление»; в tmp только `.etag`.

- [`Workspace1C/Services/UpdateService.Avalonia.cs`]: в ветке прямой установки
  (замена текущего бинарника) логировать каждый шаг и **errno/exit code**; причина,
  вероятно, в перезаписи запущенного исполняемого файла — заменить на схему:
  `mv new → target` в рамках той же ФС (atomic rename поверх работающего бинарника
  допустим на Linux) вместо copy-поверх; при занятом файле — retry с паузой и
  финальный запуск через `bash -c "sleep 1; exec <new>"` при необходимости.
- Убедиться, что `.etag` удаляется и при ошибке установки (не только при ошибке загрузки).
- Тест: расширить существующие тесты UpdateService на сценарий «установка не удалась →
  etag удалён, диагностика в журнале».

### 1.4. Issue #63 — Публикация (верификация остатка)

Пункты 18–20 комментов: дубли `LoadModule _1cws_module` в include-цепочке чистятся

## 4. Производительность (приоритет 3)

### 4.1. ThemeManager: не переустанавливать ресурсы без изменения

- [`Workspace1C/Themes/ThemeManager.Avalonia.cs:87-104`] (`ApplyTheme(bool dark)`):
  при `changed == false` сейчас всё равно вызываются `ApplyScheme` +
  `ApplyWindowButtonStyle` (полная перерисовка всех DynamicResource-потребителей —
  заметно при старте: `LoginWindow.ApplyActiveTheme` вызывает `ApplyTheme` и `ApplyScheme`
  подряд, т.е. палитра накладывается дважды). Оптимизация: при отсутствии изменений
  варианта темы пропускать повторное наложение (оставить только `ApplyScheme` при
  смене схемы); в `LoginWindow.ApplyActiveTheme` не вызывать `ApplyScheme`, если схема
  идентична уже применённой (`CurrentScheme.Equals`).
- WPF-версия [`Workspace1C/Themes/ThemeManager.cs`] — проверить тот же паттерн.

### 4.2. ExportsListWindow: сканирование папок не в конструкторе

- [`Workspace1C/Views/ExportsListWindow.Avalonia.cs:46`] — `_vm.Refresh()` синхронно
  в конструкторе (сканирование каталогов копий блокирует открытие окна при сетевых
  путях): перенести в `Opened` с выполнением в фоновой задаче + занятие кнопки
  «Обновить»; WPF-версию [`Workspace1C/Views/ExportsListWindow.xaml.cs`] — аналогично
  (проверить, где вызывается первый Refresh).

### 4.3. CliCommands: копирование файла без async-блокировки

- [`Workspace1C/Services/CliCommands.cs:320-322`] — `stream.CopyToAsync(file).GetAwaiter().GetResult()`:
  заменить на синхронный `stream.CopyTo(file, bufferSize: 1MB)` (тот же результат без
  оверхеда async-машины) либо полноценный async-метод команды. Заодно проверить
  размер буфера копирования (по умолчанию 8KB — медленно на больших dt-файлах).

### 4.4. App.axaml.cs: стартовый retry-цикл

- [`Workspace1C/App.axaml.cs:621-622`] — `Thread.Sleep(300)` в цикле ожидания при старте:
  перевести на `Task.Delay` (асинхронный контекст уже доступен) — освобождает поток
  на время стартовых ожиданий. Проверить, не UI-ли это поток (если UI — оставить,
  с комментарием).
