- Нормализовать названия (trim, схлопывание пробелов, декодирование сущностей),

- Тесты на HTML-фикстурах: заголовки `<h2>`, `<summary>`, `<div class="group">`,
  известные названия, отсутствие разделов, фолбэк.

**1.3. Убрать «добавки» из подписей файлов.**

- Обе галочки: `имя_файла`.
- Разделитель — ` - `; отсутствующие части пропускаются; сортировка списка по
  итоговой строке (OrdinalIgnoreCase).

**Критерий:** строка выбора раздела видна при наличии разделов; чекбокс слева
без текста; подписи без типа дистрибутива; сортировка по итоговой строке;

### Задача 2. Issue #164 — повторный запрос пароля при запуске из трея

**Границы:** `Workspace1C/App.xaml.cs` (и `App.axaml.cs` для Avalonia),
`Workspace1C.Tests/Issue164AccountPasswordPromptTests.cs` (+ новый тест политики).

**Причина (подтверждена кодом):** в `OnStartup` окно входа
(`LoginWindow.ShowLogin`, строки ~125–154) показывается **до** проверки
одиночного экземпляра (mutex, строки ~220–254). Повторный запуск ярлыком
создаёт новый процесс, который сначала спрашивает пароль, и только потом
обнаруживает уже работающий экземпляр.

**Что сделать:**
- Прочитать настройки активного профиля (в т.ч. `AllowMultipleInstances`)
  до окна входа; вынести проверку одиночного экземпляра и
  `StartActivationListener` **до** показа `LoginWindow`.
- При уже работающем экземпляре: `SignalExistingInstance()` + `Shutdown()` —
  без окна входа. Существующий экземпляр активируется из трея
  (`ActivateMainWindow` → `RestoreFromTrayPublic`), пароль не запрашивается,
  если приложение не заблокировано (`IsAppLocked == false`).
- Сохранить поведение `--register/--launch/--designer` (обрабатываются до гейта).
- Вынести решение в чистую функцию (например,
  `StartupInstancePolicy.IsPrimaryInstance(allowMultiple, createdNew)`) и покрыть тестами.
- Проверить оба фронта: WPF `App.xaml.cs` и Avalonia `App.axaml.cs`.

**Критерий:** при свёрнутом в трей приложении запуск ярлыка активирует
существующее окно без запроса пароля; при заблокированном приложении пароль
по-прежнему требуется; второй полноценный процесс не создаётся.

### Задача 3. Issue #159 — раскрыватель, иконки и размеры окон редакторов (Linux)

**Границы:** `Workspace1C/Themes/Controls.axaml` (тема `ModernTreeItem`),
`Views/UtilitiesMenuEditorWindow.Avalonia.cs`,
`Views/ContextMenuEditorWindow.Avalonia.cs`,
`Views/TrayMenuEditorWindow.Avalonia.cs`,
`Views/UtilitiesGroupEditWindow.Avalonia.cs`,
`Services/DialogWorkAreaPolicy.cs`,
`Workspace1C.Tests/Issue159UtilitiesContextMenuTests.cs` (+ новые тесты).

**3.1. Раскрыватель дерева.**
- Причина: раскрыватель — вращающийся `Path` с `RenderTransform`; при раскрытии
  глиф визуально «схлопывается в точку», зона клика ограничена.
- Заменить вращение на два явных глифа по состоянию
  (`IconChevronRight` / `IconChevronDown`) через стили `:checked`, без
  `RenderTransform`; размер 16×16, колонка 24, `HorizontalAlignment=Stretch`,
  `VerticalAlignment=Stretch`, `MinWidth/MinHeight=24` — клик по всей колонке.
- Тема общая, поэтому исправление автоматически применяется во всех редакторах
  (Утилиты, Контекстное меню, Меню в трее, обозреватель метаданных и т.д.).
- Проверить, что строка остаётся кликабельной целиком (ПКМ/выбор).

**3.2. Иконки узлов.**
- Убедиться, что `DisplayIconGeometryKey` для всех редакторов даёт
  различимые иконки (не «точку» и не одну папку); для неизвестного ключа —
  осмысленный фолбэк, одинаковый в редакторах.

**3.3. Размеры окон правки.**
- Причина: у редакторов фиксированная высота и внешняя прокрутка — на Linux
  скролл во всех 4 окнах.
- Ввести/настроить профили `DialogWorkAreaPolicy` для редакторов и открывать
  окна по содержимому: `SizeToContent = Height`, `MaxHeight` — по рабочей
  области, `MinHeight` — разумный минимум; прокрутка только как аварийный режим.
- Применить к 4 окнам правки: «Утилиты», «Контекстное меню», «Меню в трее»,
  «Мои программы» (и групповым окнам, если скролл остаётся).
- Тесты на политику размеров (высота по содержимому, кламп по рабочей области).

**Критерий:** раскрыватель не «превращается в точку», клик по всей колонке;
иконки различимы; в 4 окнах правки нет постоянного скролла при нормальном
разрешении; на маленьком экране окна клампятся по рабочей области.

### Задача 4. Issue #158 — «Мои программы»: закрытие, дубли окон, обновление списка

**Границы:** `Workspace1C/Views/CustomProgramsWindow.Avalonia.cs`,
`Views/CustomProgramsWindow.xaml.cs`,
`Views/SettingsWindow.Avalonia.cs`, `Views/SettingsWindow.xaml.cs`,
`ViewModels/CustomProgramsViewModel.cs`,
`Models/CustomProgram.cs`,
`Views/ModalWindowBase.cs` (при необходимости),
`Workspace1C.Tests/Issue158MyProgramsSaveTests.cs` (+ новые тесты).

**4.1. Диагностика.**
- Воспроизвести с `CM_MODAL_TRACE=1`, снять `OnClosing/OnClosed/ShowDialogSync`
  из `docs/_crash_158.log` (создать лог).
- Проверить сценарий открытия из `SettingsWindow` (вложенный `ShowDialogSync`
  внутри уже модального окна настроек).

**4.2. Окно обязано закрываться.**
- «Отмена», крестик, Esc, закрытие после ошибки — всегда закрывают окно;
  `OnClosing` не отменяет закрытие и не пробрасывает исключение.
- Если причина — вложенный `ShowDialogSync` из модальных настроек: открывать
  редактор немодально (`Show()` с `Owner`) либо через безопасный
  `ShowDialogSync` с гарантированным снятием кадра; закрытие — через
  `Dispatcher.UIThread.Post(Close)` при необходимости.
- Ошибка сохранения показывается, но не блокирует закрытие.

**4.3. Запрет двух окон редактора.**
- Статический guard `IsOpen` (или поиск уже открытого окна у владельца):
  повторное открытие активирует существующее окно, второе не создаётся;
  флаг сбрасывается в `Closed` (в `finally`, чтобы не «залипнуть»).

**4.4. Список обновляется при правке.**
- Причина: `CustomProgram` — простой модель без `INotifyPropertyChanged`,
  поэтому переименование не видно в списке до переоткрытия.
- Реализовать `INotifyPropertyChanged` для `CustomProgram` (Name, FilePath,
  Arguments, WorkingDirectory, IconPath, UseCustomIcon, Order) либо обернуть
  элементы в item-VM; список обновляется сразу.
- Удаление программы не должно бросать исключение: обработка и журналирование
  ошибок, безопасное удаление значка/иконки.

**Критерий:** окно закрывается любым штатным способом, в т.ч. после ошибки;
одновременно открыто не более одного окна; переименование сразу видно в списке;
удаление и сохранение не показывают необработанных ошибок.
