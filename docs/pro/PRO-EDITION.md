# Workspace 1C ПРО: устройство редакций и лицензирования

Документ описывает переход с полностью бесплатной 1.0.x на две редакции начиная с **2.0.0.0**.

## 1. Редакции

| | Бесплатная | ПРО |
|---|---|---|
| Цена | 0 | платная, бессрочная в рамках старшей версии (2.x.x.x) |
| Привязка | — | к компьютеру (код компьютера) |
| Код | публичный репозиторий, MIT | ядро — публичное; ПРО-модули — приватный репозиторий `Workspace1C.Pro` |
| Сборка | любая (в т.ч. собранная из исходников) | официальная сборка из GitHub Releases |

Официальный exe/бинарник Linux **один**: без ключа он работает как бесплатная редакция,
с ключом открывает ПРО-функции. Собранная из публичных исходников программа ПРО-модулей
не содержит: пункты ПРО видны с отметкой «ПРО» и предлагают скачать официальную сборку.

Версии 1.0.x остаются под MIT навсегда — это нельзя отозвать, и это нормально:
ПРО продаёт новые возможности и развитие, а не то, что уже раздано.

## 2. Состав ПРО

Перечень — в одном месте, `Workspace1C/Services/Licensing/ProFeature.cs`.

**Существующие инструменты администратора (были бесплатны в 1.0.x):**

- Мониторинг и оповещения (`ServerAlerts`)
- Команды Telegram-бота (`TelegramBot`)
- MCP-сервер для ИИ-агентов (`--mcp`) (`Mcp`)
- Миграция баз между кластерами (`ClusterMigration`)
- Тестовый контур / «Развернуть тестовую копию» (`TestDeploy`)
- Массовая загрузка конфигурации из .cf (`MassLoadCf`)

**Новые функции 2.x:**

- Конвейеры обслуживания (`Pipelines`)
- Консоль запросов по нескольким базам (`MultiBaseQuery`)
- Сравнение окружения баз (`EnvironmentDiff`)
- Автотесты в тестовом контуре (`AutoTests`)
- Тренды производительности по техжурналу (`PerformanceTrends`)
- Журнал аудита действий (`AuditLog`)
- Копии в S3 и шифрование копий (`CloudBackup`)

**Остаются бесплатными** всё прочее, в том числе новые «быстрые» функции 2.x:
внешние отчёты и обработки по списку баз (issue #91), значок запуска при отладке
из Конфигуратора (issue #103), быстрый доступ к серверам по RDP/SSH.

> Существующие админ-функции уже опубликованы под MIT в 1.0.x. В официальной сборке 2.x
> они закрываются лицензией, их код остаётся в публичном репозитории. Защита этих
> функций — организационная (официальные сборки, обновления, поддержка), не техническая.
> Новые функции 2.x пишутся только в приватном репозитории.

## 3. Лицензионный ключ

### Код компьютера

`MachineIdProvider` берёт стабильный идентификатор ОС:

- Windows — `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`;
- Linux — `/etc/machine-id` (запасной вариант — `/var/lib/dbus/machine-id`).

Код компьютера = первые 10 байт `SHA-256("Workspace1C|" + id)` в Base32 Крокфорда,
по 4 символа через дефис: `7K2M-QX9P-4RTA-0HCW`. Сам идентификатор ОС никуда не уходит.
Переустановка ОС меняет код — ключ перевыпускается бесплатно.

### Формат ключа

```
W1C2.<payload base64url>.<signature base64url>
```

- `payload` — JSON (UTF-8):
  `{"v":1,"id":"…","edition":"pro","major":2,"machine":"7K2M-QX9P-4RTA-0HCW","owner":"ООО Ромашка","email":"…","issued":"2026-11-08"}`
- `signature` — ECDSA P-256 / SHA-256 (формат IEEE P1363, 64 байта) над байтами
  строки `W1C2.<payload base64url>`.
- Открытый ключ встроен в программу (`LicenseVerifier.PublicKey`), закрытый хранится
  только у правообладателя (утилита выпуска ключей в приватном репозитории).
  ECDSA P-256 — потому что он есть в .NET «из коробки» и на Windows, и на Linux;
  внешних пакетов не нужно.

### Проверка

Ключ действителен, если одновременно:

1. подпись верна;
2. `edition == "pro"`;
3. `major` совпадает со старшим числом версии программы (2 для 2.x.x.x);
4. `machine` совпадает с кодом этого компьютера.

Срока действия нет. Проверка полностью офлайн, без обращения к серверу.

Ключ хранится в `license.key` в каталоге данных программы (`%APPDATA%\Workspace1C`,
`~/.config/Workspace1C`, в портативном режиме — `Workspace1C-Data`). Файл не входит
в синхронизацию настроек: на другом компьютере ключ всё равно не подойдёт.

### Переход на 3.x

Ключ на 2.x не открывает 3.x — программа показывает «Ключ выпущен для версии 2.x»
и предлагает обновить лицензию. Остаться на последней 2.x можно бессрочно.

## 4. Как пользователь покупает и активирует

1. «Утилиты» → «О программе» → «Лицензия» (или клик по пункту с отметкой «ПРО»):
   окно показывает редакцию, код компьютера и кнопку «Скопировать код».
2. Пользователь оплачивает и присылает код компьютера.
3. Правообладатель выпускает ключ утилитой `LicenseIssuer` (приватный репозиторий):
   `LicenseIssuer issue --machine 7K2M-QX9P-4RTA-0HCW --owner "ООО Ромашка" --email a@b.ru`.
4. Пользователь вставляет ключ в окно «Лицензия» → «Активировать». Без перезапуска.

Командная строка: `Workspace1C --license-info [--json]`, `Workspace1C --activate "W1C2.…"`.
ПРО-команды CLI (`--mcp`) без ключа завершаются кодом **6** («требуется ПРО»).

## 5. Устройство кода (open-core)

```
Публичный репозиторий Workspace1C               Приватный Workspace1C.Pro
├─ Services/Licensing/                          ├─ src/                ← ПРО-модули 2.x
│   ProFeature.cs        перечень ПРО-функций   │   Pipelines/, MultiBaseQuery/, …
│   MachineIdProvider.cs код компьютера         │   ProModules.cs   ← partial AppServices.RegisterProModules
│   LicenseKey.cs        разбор ключа           ├─ tools/LicenseIssuer/  ← выпуск ключей
│   LicenseVerifier.cs   проверка подписи       └─ README.md
│   EditionService.cs    текущая редакция
└─ Workspace1C.csproj  ── если рядом есть ..\Workspace1C.Pro\src, его *.cs/*.xaml
                         включаются в сборку и определяется символ PRO_MODULES
```

- ПРО-код компилируется **в ту же сборку** (а не загружается плагином): так работают
  `partial`-классы окон, single-file публикация и обе платформы без изменений.
- Точка подключения — `static partial void RegisterProModules(IServiceCollection)`
  в `AppServices`: без приватного репозитория у метода нет реализации, и компилятор
  удаляет вызов.
- Пункт меню «Утилиты» с `ProFeature` строится всегда; при отсутствии лицензии
  он помечается «ПРО» и вместо действия открывает окно «Лицензия».
- Проверка в коде: `EditionService.Current.Has(ProFeature.Pipelines)`.

### Сборка

- Бесплатная (из публичных исходников): как сейчас.
- Официальная: склонировать `Workspace1C.Pro` рядом (`G:\h\Workspace1C.Pro`) — csproj
  подхватит его сам. В GitHub Actions — шаг checkout приватного репозитория с секретом
  `PRO_REPO_TOKEN` (fine-grained PAT с правом чтения `Workspace1C.Pro`).

## 6. Риски и честные ограничения

- .NET-сборку можно декомпилировать и пропатчить проверку. Это задерживает, но не
  исключает взлом. При необходимости позже — обфускация ПРО-части.
- Код компьютера меняется при переустановке ОС и клонировании виртуальных машин —
  нужен простой порядок бесплатного перевыпуска.
- Тексты README, «Условия лицензии» и раздел «О программе» нужно обновить до 2.0:
  сейчас там «программа полностью бесплатна».
- Внешние участники (PR от 7OH и др.) вносили код под MIT — использовать его в
  платной сборке MIT разрешает; уведомление MIT нужно сохранить.
