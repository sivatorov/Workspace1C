## [1.0.1.123] — 2026-11-25

### Исправлено

- **Скачивание версии платформы: разделы, галочка разрядности и подписи файлов
  (issue #167, Windows и Linux).**
  - Галочка фильтра разрядности перенесена **слева от подписи поля «Файл»**, без
    дополнительного текста («Только моя разрядность» убрана); назначение поясняет
    подсказка. Строка выбора раздела (галочка + `ComboBox`) видима только при
    `HasSections`.
  - Причина «поле выбора раздела не появилось»: `OneCPlatformCatalogParser.ExtractGroupHeaders`
    распознавал разделы только по `<b>/<strong>`, а страница `version_files` размечает
    их иначе. Теперь учитываются `<h1>…<h4>`, `<summary>`, `<caption>`, `<legend>`,
    элементы с CSS-классом `group`/`section`/`header` и известные названия разделов
    («Windows (64-bit)», «Linux (64-bit)» и т.п.). Если заголовков нет, но файлы
    относятся к разным семействам ОС, разделы синтезируются по семейству и
    разрядности; при одном семействе разделов нет (`HasSections=false`).
  - Из подписей файлов убраны «добавки» типа «Полный клиент (rar)», «Тонкий клиент
    (zip)», «Пакет deb» — они часто не соответствуют содержимому. Подпись собирает
    `PlatformFileDisplayName.Compose`: без галочек — `Раздел - x64 - имя_файла`,
    с учётом разрядности — `Раздел - имя_файла`, с учётом раздела — `x64 - имя_файла`,
    с обеими галочками — `имя_файла`. Список сортируется по итоговой строке.
  - `PlatformDistributionOption.DisplayName` для остальных окон не изменён — окно
    скачивания задаёт подпись через `DisplayNameOverride`.

- **Повторный запрос пароля при запуске ярлыком из трея (issue #164, Windows и Linux).**
  - Причина: в `OnStartup` окно входа (`LoginWindow.ShowLogin`) показывалось **до**
    проверки одиночного экземпляра (mutex/файловый lock). Повторный запуск ярлыком
    создавал новый процесс, который сначала спрашивал пароль профиля и только потом
    обнаруживал уже работающий экземпляр.
  - Настройки активного профиля (включая `AllowMultipleInstances`) читаются до окна
    входа; проверка одиночного экземпляра и `StartActivationListener` перенесены
    **до** `LoginWindow.ShowLogin`. Второй процесс при `AllowMultipleInstances=false`
    вызывает `SignalExistingInstance()` + `Shutdown()` и не показывает вход —
    работающее окно активируется из трея без запроса пароля.
  - Обработка команд `--register/--launch/--designer` по-прежнему выполняется до
    гейта одиночного экземпляра. При заблокированном приложении (`IsAppLocked == true`)
    пароль по-прежнему запрашивает уже работающий экземпляр.
  - Решение вынесено в чистую политику `StartupInstancePolicy`
    (`ShouldUseSingleInstanceGate`, `ShouldActivateExistingInstance`,
    `IsPrimaryInstance`, `ShouldShowLogin`); при `AllowMultipleInstances=true` запуск
    и вход работают как прежде.

- **Linux: раскрыватель дерева, иконки узлов и размеры окон редакторов (issue #159).**
  - Причина «значок свёртки превращается в точку»: раскрыватель был одним `Path`
    с `RenderTransform` (поворот на 90°). В общей теме `ModernTreeItem` (и в
    `GroupPickerTreeItem`) поворот заменён двумя явными глифами по состоянию:
    свёрнуто — `IconChevronRight`, раскрыто — `IconChevronDown`; `RenderTransform`
    больше не используется.
  - Зона клика раскрывателя — вся колонка и высота строки
    (`HorizontalAlignment/VerticalAlignment=Stretch`, `MinWidth/MinHeight=24`,
    прозрачный фон), поэтому клик по любому месту колонки раскрывает/сворачивает
    узел. Тема общая, поэтому исправление действует во всех редакторах.
  - Иконки узлов: контекстное меню строит `DisplayIconGeometryKey` по каталогу,
    разделитель — `IconMinus`, неизвестный ключ — единый фолбэк `IconFolder`.
    «Утилиты» и «Меню в трее» приведены к тому же правилу.
  - Размеры четырёх окон правки (`Utilities`, `ContextMenu`, `TrayMenu`,
    `CustomPrograms`): `SizeToContent = SizeToContent.Height`, фиксированная высота
    убрана, `MaxHeight` клампится по рабочей области через `DialogWorkAreaPolicy`,
    дерево/список прокручиваются внутри. Постоянный внешний скролл на Linux исчезает,
    на маленьком экране прокрутка остаётся аварийным режимом.

- **Linux: «Мои программы» — закрытие окна, дубли окон и обновление списка
  (issue #158).**
  - Причина «окно невозможно закрыть»: шаблон строки списка обращался к
    `program.Name` без проверки на `null`, а `ContentPresenter` Avalonia строит
    строку и для пустого содержимого (удаление записи, пересоздание контейнера,
    закрытие окна). `NullReferenceException` прерывал закрытие. Теперь шаблон
    null-безопасен, сбой построения строки логируется.
  - Имя в строке списка привязано к модели (`CustomProgram` реализует
    `INotifyPropertyChanged`) — переименование сразу видно в списке.
  - Одновременно открыто не более одного редактора (`CustomProgramsEditorGuard`,
    `CustomProgramsWindow.ShowEditor`); повторный клик активирует открытое окно,
    слот освобождается в `finally`/`Closed`.
  - «Отмена», Esc, крестик и закрытие после сохранения идут через `CloseSafely`
    с повторным закрытием из диспетчера — окно закрывается даже после сбоя.
  - Удаление программы не бросает исключение: ошибка пишется в журнал
    (`LastDeleteError`), ссылка на иконку снимается без удаления файла пользователя.
  - Диагностика: [`docs/_crash_158.log`](docs/_crash_158.log).

### Тесты

- `Issue167PlatformDownloadSectionTests` — парсер (`<h2>`, `<summary>`, `class`,
  известные названия, отсутствие разделов, фолбэк по семействам), четыре комбинации
  подписи, сортировка и паритет WPF/Avalonia (галочка без текста).
- `Issue164AccountPasswordPromptTests` — политика запуска: второй экземпляр
  активирует существующий без окна входа, `AllowMultipleInstances=true` стартует
  полноценно, первичный экземпляр идёт обычным путём; source-guard порядка
  «гейт до `LoginWindow.ShowLogin`» и «CLI до гейта» в WPF/Avalonia.
- `Issue159UtilitiesContextMenuTests` (расширены) — source-guard темы
  `ModernTreeItem`: два глифа `IconChevronRight`/`IconChevronDown`, отсутствие
  `RenderTransform`/`RotateTransform`, зона клика `MinWidth/MinHeight=24` и
  `Stretch`; различимость иконок; политика размеров и `SizeToContent.Height` во
  всех четырёх окнах правки.
- `Issue158CustomProgramsWindowTests` — `PropertyChanged` модели, guard одного окна,
  удаление при сбое списка не бросает и логирует, удаление снимает ссылку на иконку,
  null-безопасный шаблон и привязка имени, безопасное закрытие в WPF и Avalonia.

### Что проверить

- **Скачивание платформы (#167):** откройте окно скачивания — галочка разрядности
  слева от подписи поля «Файл» без лишнего текста; при наличии разделов появляется
  строка выбора раздела; подписи файлов без «Полный клиент (rar)»/«Пакет deb»;
  список отсортирован по итоговой строке. Поведение одинаково в WPF и Avalonia.
- **Запуск из трея (#164):** сверните приложение в трей и запустите ярлык — окно
  активируется без запроса пароля, второй процесс не создаётся. При заблокированном
  приложении пароль по-прежнему требуется; при `AllowMultipleInstances=true` запуск
  и вход работают как раньше.
- **Редакторы на Linux (#159):** раскрыватель не «превращается в точку», клик по
  всей колонке раскрывает узел; иконки узлов различимы; в четырёх окнах правки нет
  постоянного внешнего скролла при нормальном разрешении, на маленьком экране окна
  клампятся по рабочей области.
- **«Мои программы» (#158):** окно закрывается «Отменой», Esc, крестиком и после
  сохранения (в том числе после ошибки); одновременно открыто не более одного окна;
  переименование сразу видно в списке; удаление не показывает необработанных ошибок.

### Паритет WPF/Avalonia и локализация

- Все четыре исправления реализованы в обеих оболочках: WPF (`App.xaml.cs`,
  `Views/*.xaml.cs`) и Avalonia (`App.axaml.cs`, `Views/*.Avalonia.cs`,
  `Themes/Controls.axaml`).
- Новые пользовательские строки отсутствуют; существующие подписи и подсказки
  сохранены в русской и английской локализациях, ключи `Localization/Languages/*.json`
  не менялись.

Windows-бинарь собирается штатным `build-windows-single-file.ps1 -Configuration Release`;
smoke-проверка `Workspace1C.exe --list` (код 0) и `--license-info --json` →

`build-linux-single-file.ps1 -Configuration Release` (`-p:ForceLinux=true`,
linux-x64); локальный запуск на Windows невозможен, запуск и smoke-тест Linux-бинаря
выполняются в CI на `ubuntu-latest`. Подробности — в
