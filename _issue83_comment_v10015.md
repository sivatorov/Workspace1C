Исправлено в версии **1.0.1.5** (Windows и Linux):

Вкладка «Лицензии» в «Серверы 1С» — утилита `ring` теперь запускается, даже если установлена как командный файл в PATH:

- в [`RingLicenseService.ToLaunchCommand`](Workspace1C/Services/RingLicenseService.cs) найденный `where.exe ring`/`which ring` путь разлагается на «исполняемый вызов»: `.cmd`/`.bat` запускаются через `cmd.exe /c` — ровно так их выполняет командная строка пользователя (прямой `CreateProcess` не находит командные файлы по `PATHEXT` — отсюда «Не удается найти указанный файл»);
- `.exe`/`.com` и нативные файлы Linux запускаются напрямую по полному пути;
- улучшен текст подсказки `BuildUnavailableMessage`: `ring` может быть установлен как `.exe` в каталоге bin платформы либо добавлен в PATH (в т.ч. как командный файл `.cmd`/`.bat`), проверка выполняется так же, как в командной строке.

Покрыто тестами [`Issue83LicenseTabTests.cs`](Workspace1C.Tests/Issue83LicenseTabTests.cs): `ToLaunchCommand` для `.exe`/`.cmd`/нативных и кандидат из `where`-пути.

Спасибо за сообщение! Проверьте, пожалуйста, в новом релизе.
