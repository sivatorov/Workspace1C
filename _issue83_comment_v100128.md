@7OH, спасибо за скриншот — по нему разобрался, все три симптома были связаны.

Что исправлено в [v1.0.1.28](https://github.com/sivatorov/Workspace1C/releases/tag/v1.0.1.28):

1. **«Файл не найден» сверху больше не залипает.** Это было сообщение от клика по колонке
   «Модуль» при пустом пути к файлу — оно оставалось в строке статуса навсегда. Теперь сообщение
   временное: через 6 секунд возвращается прежний статус вкладки (или пусто).

2. **Пустая таблица — программа искала файлы лицензий не везде.** Раньше читался только первый
   существующий каталог `%ProgramData%\1C\1Cv8\licenses`. Теперь обходятся ВСЕ места хранения 1С:
   - `%ProgramData%\1C\1Cv8\licenses`;
   - `%ProgramData%\1C\licenses` (без 1Cv8 — именно его часто использует платформа);
   - пер-пользовательские `%LOCALAPPDATA%\1C\1cv8\licenses` и `%APPDATA%\1C\1cv8\licenses`.
   Дубли по имени файла отбрасываются. Лицензии из per-user каталога больше не теряются.

3. **Окно деталей (клик по «Серийному номеру») теперь показывает всё:** распознанные поля
   (владелец, рег. номер, пользователь/компьютер, даты, количество мест) И полное содержимое
   файла лицензии — многострочно, с прокруткой, а не одну строку, обрезанную на 400 символов.
   Разбор формата *.lic улучшен: распознаются, в частности, компактные даты вида 20260907085731
   (как в имени файла из вашего скриншота). Если файл прочитать не удалось — в деталях видна
   причина сбоя, а не только имя файла.

Исправлено на обеих платформах (Windows и Linux).

Issue не закрываю — прошу проверить на [v1.0.1.28](https://github.com/sivatorov/Workspace1C/releases/tag/v1.0.1.28). Если таблица всё ещё пуста — пришлите, пожалуйста, ZIP диагностики («Утилиты → Собрать диагностику»): теперь в лог попадает перечень проверенных каталогов лицензий и количество найденных файлов, по нему будет видно, где платформа хранит *.lic на вашей машине.
