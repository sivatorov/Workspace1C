# Workspace 1C ПРО: устройство редакций и лицензирования

Документ описывает лицензирование начиная с версии **1.0.1.119** (актуальная версия —
**1.0.1.120**) и переход к редакциям
2.x. Политика: **публичное ядро (public core) в 1.x остаётся бесплатным**, а ключом
`major=1` открываются **только новые функции 2.x**. Они вкомпилированы в основную
программу, но закрыты лицензией: до активации ключа недоступны, после активации
работают сразу, без перезапуска. Версии до 1.0.1.119 не переделываются.

## 1. Редакции

| | Бесплатная | ПРО |
|---|---|---|
| Цена | 0 | **2000 ₽**, бессрочная в рамках старшей версии (major) |
| Привязка | — | к компьютеру (код компьютера) |
| Код | публичный репозиторий, MIT | ядро — публичное; ПРО-модули — приватный репозиторий `Workspace1C.Pro` |
| Сборка | собранная из публичных исходников: модулей 2.x нет | **та же основная программа** из GitHub Releases: модули 2.x внутри, доступ закрыт лицензией |

### Политика 1.0.1.120

| Группа функций | Без ключа в 1.x | С ключом `major=1` |
|---|---|---|
| **Public core**: `ServerAlerts`, `TelegramBot`, `Mcp`, `ClusterMigration`, `TestDeploy`, `MassLoadCf` | **доступны** (как в 1.0.1.118) | доступны |
| **Новые 2.x**: `Pipelines`, `MultiBaseQuery`, `EnvironmentDiff`, `AutoTests`, `PerformanceTrends`, `AuditLog`, `CloudBackup` | видны в меню с отметкой « · ПРО» и подсказкой «требуется ключ»; клик открывает окно «Лицензия» и не выполняет действие. В сборке из публичных исходников — «только в официальной сборке» | доступны сразу после активации: модули (`PRO_MODULES`) уже вкомпилированы в основную программу |
| Всё, чего нет в `ProFeature` | доступно | доступно |

Правило в коде: [`EditionService.Has()`](../../Workspace1C/Services/Licensing/EditionService.cs)
для public core в 1.x возвращает `true` без ключа
(`VersionInfo.Major() < 2 && ProFeatures.IsInPublicCore(feature)`), а для новых 2.x
действует `IsPro && HasProModules`. Тесты `Issue106FreePublicCoreTests` и
`ProLicensingTests` — стражи бесплатности public core.

### Оплата и контакты

Купить ПРО можно через контакты проекта:

- Telegram-канал: [t.me/Workspace1C](https://t.me/Workspace1C);
- Issues репозитория: <https://github.com/sivatorov/Workspace1C/issues>;
- репозиторий проекта: <https://github.com/sivatorov/Workspace1C>.

Раздел покупки в README — «ПРО-версия»:
<https://github.com/sivatorov/Workspace1C#-про-версия>
(там же — состав ПРО и пошаговый порядок покупки).

Основная программа (exe/бинарник Linux) **одна** и выпускается **с модулями ПРО
внутри**: без ключа она работает как бесплатная редакция, с ключом `major=1` сразу
открывает новые функции 2.x. Отдельной «ПРО-сборки» нет — лицензия лишь снимает
закрытие с уже вкомпилированных модулей. Собранная вручную из публичных исходников
программа (без клона `Workspace1C.Pro`) ПРО-модулей не содержит: пункты 2.x видны
с отметкой « · ПРО» и статусом «только в официальной сборке».

Версии 1.0.x остаются под MIT навсегда — это нельзя отозвать, и это нормально:
ПРО продаёт новые возможности и развитие, а не то, что уже раздано.

## 2. Состав ПРО

Перечень — в одном месте, `Workspace1C/Services/Licensing/ProFeature.cs`.

**Public core — бесплатен в 1.x (ключ не требуется):**

- Мониторинг и оповещения (`ServerAlerts`)
- Команды Telegram-бота (`TelegramBot`)
- MCP-сервер для ИИ-агентов (`--mcp`, `Mcp`)
- Миграция баз между кластерами (`ClusterMigration`)
- Тестовый контур / «Развернуть тестовую копию» (`TestDeploy`)
- Массовая загрузка конфигурации из .cf (`MassLoadCf`)

**Новые функции 2.x — требуют ключ `major=1` и официальную сборку:**

- Конвейеры обслуживания (`Pipelines`)
- Консоль запросов по нескольким базам (`MultiBaseQuery`)
- Сравнение окружения баз (`EnvironmentDiff`)
- Автотесты в тестовом контуре (`AutoTests`)
- Тренды производительности по техжурналу (`PerformanceTrends`)
- Журнал аудита действий (`AuditLog`)
- Копии в S3 и шифрование копий (`CloudBackup`)

**Остаются бесплатными** всё прочее, в том числе новые «быстрые» функции 2.x:
внешние отчёты и обработки по списку баз (issue #91), значок запуска при отладке
из Конфигуратора (issue #103), быстрый доступ к серверам по RDP/SSH.

> Существующие админ-функции (public core) уже опубликованы под MIT в 1.0.x и в
> редакции 1.x остаются бесплатными без ключа. В официальной сборке 2.x их код также
> остаётся в публичном репозитории; защита — организационная (официальные сборки,
> обновления, поддержка), не техническая. Новые функции 2.x пишутся только в приватном
> репозитории.

## 3. Лицензионный ключ

### Код компьютера

`MachineIdProvider` берёт стабильный идентификатор ОС:

- Windows — `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`;
- Linux — `/etc/machine-id` (запасной вариант — `/var/lib/dbus/machine-id`).

Код компьютера = первые 10 байт `SHA-256("Workspace1C|" + id)` в Base32 Крокфорда,
по 4 символа через дефис: `7K2M-QX9P-4RTA-0HCW`. Сам идентификатор ОС никуда не уходит.
Переустановка ОС меняет код — ключ перевыпускается бесплатно.

### Формат ключа

```
W1C2.<payload base64url>.<signature base64url>
```

- `payload` — JSON (UTF-8):
  `{"v":1,"id":"…","edition":"pro","major":1,"machine":"7K2M-QX9P-4RTA-0HCW","owner":"ООО Ромашка","email":"…","issued":"2026-11-25"}`
- `signature` — ECDSA P-256 / SHA-256 (формат IEEE P1363, 64 байта) над байтами
  строки `W1C2.<payload base64url>`.
- Открытый ключ встроен в программу (`LicenseVerifier.PublicKey`), закрытый хранится
  только у правообладателя (утилита выпуска ключей в приватном репозитории).
  ECDSA P-256 — потому что он есть в .NET «из коробки» и на Windows, и на Linux;
  внешних пакетов не нужно.
- Префикс `W1C2.` — это обозначение формата ключа, а не номер версии программы.

### Ключи для 1.x

- [`KeyIssuer.DefaultMajor`](../../Workspace1C.Pro/tools/LicenseIssuer/KeyIssuer.cs) равен **1**,
  поэтому `LicenseIssuer issue --machine … --owner …` по умолчанию выпускает ключ для 1.x.
  Для явности в команде указывают `--major 1`.
- [`LicenseVerifier`](../../Workspace1C/Services/Licensing/LicenseVerifier.cs) требует
  `key.Major == programMajor`; для 1.0.1.120 это `major = 1`.
- Ключи с `major = 2` в 1.0.1.120 **не подойдут** — программа сообщит, что ключ выпущен
  для другой версии.

### Проверка

Ключ действителен, если одновременно:

1. подпись верна;
2. `edition == "pro"`;
3. `major` совпадает со старшим числом версии программы (1 для 1.x, 2 для 2.x.x.x);
4. `machine` совпадает с кодом этого компьютера.

Срока действия нет. Проверка полностью офлайн, без обращения к серверу.

Ключ хранится в `license.key` в каталоге данных программы (`%APPDATA%\Workspace1C`,
`~/.config/Workspace1C`, в портативном режиме — `Workspace1C-Data`). Файл не входит
в синхронизацию настроек: на другом компьютере ключ всё равно не подойдёт.

### Переход на 3.x

Ключ на 2.x не открывает 3.x — программа показывает «Ключ выпущен для версии 2.x»
и предлагает обновить лицензию. Остаться на последней 2.x можно бессрочно.

## 4. Как пользователь покупает и активирует

Актуальные пункты меню (WPF и Avalonia):

- **«Утилиты» → «Справка» → «Лицензия…»** — редакция, код компьютера, кнопки
  «Скопировать код», «Активировать», «Удалить ключ»; в бесплатной редакции — кнопка
  «Купить».
- **«Утилиты» → «Справка» → «Как купить ПРО…»** — окно с пошаговой инструкцией,
  строкой про `major=1` для 1.x, официальными контактами и карточкой «что остаётся
  бесплатным».
- **«Настройки» → вкладка «О программе»** — блок «Лицензия»: редакция (бесплатная или
  ПРО), владелец, версия ключа и дата выпуска, код компьютера, статус ключа; кнопки
  «Лицензия…» и «Как купить ПРО…».

Порядок покупки:

1. Скопировать **код компьютера** в окне «Лицензия» («Скопировать код»), командой
   `Workspace1C --license-info` или из блока «Лицензия» на вкладке «О программе».
2. Оплатить **2000 ₽** (см. «Оплата и контакты» выше) и отправить код компьютера,
   указав, что нужен ключ **`major=1`** (для 1.x).
3. Правообладатель выпускает ключ утилитой `LicenseIssuer` (приватный репозиторий):
   `LicenseIssuer issue --machine 7K2M-QX9P-4RTA-0HCW --owner "ООО Ромашка" --email a@b.ru --major 1`.
4. Пользователь вставляет ключ в окно «Лицензия» → «Активировать». Без перезапуска.
   Альтернатива — `Workspace1C --activate "W1C2.…"`.

Статусы функций в окне «Лицензия» честные:

- **«доступна»** — функция работает (public core в 1.x; 2.x с ключом `major=1` в
  официальной сборке);
- **«требуется ключ»** — 2.x в официальной сборке без ключа;
- **«только в официальной сборке»** — 2.x в публичной сборке (модулей ПРО нет);
- **«в разработке»** — функция ещё не реализована.

Блок «Лицензия» и метка редакции реализованы в обеих оболочках: WPF (Windows)
и Avalonia (Linux). После активации или удаления ключа блок обновляется сразу,
без перезапуска. При действительном ключе в заголовке главного окна появляется
метка `★` перед названием — `★ Workspace 1C v<версия>`; она также обновляется
сразу после активации/удаления ключа.

Командная строка: `Workspace1C --license-info [--json]`, `Workspace1C --activate "W1C2.…"`.
ПРО-команды CLI (`--mcp` и модули 2.x) без ключа завершаются кодом **6** («требуется ПРО»).

## 5. Устройство кода (open-core)

```
Публичный репозиторий Workspace1C               Приватный Workspace1C.Pro
├─ Services/Licensing/                          ├─ src/                ← ПРО-модули 2.x
│   ProFeature.cs        перечень ПРО-функций   │   Pipelines/, MultiBaseQuery/, …
│   MachineIdProvider.cs код компьютера         │   ProModules.cs   ← partial AppServices.RegisterProModules
│   LicenseKey.cs        разбор ключа           ├─ tools/LicenseIssuer/  ← выпуск ключей
│   LicenseVerifier.cs   проверка подписи       └─ README.md
│   EditionService.cs    текущая редакция
└─ Workspace1C.csproj  ── если рядом есть ..\Workspace1C.Pro\src, его *.cs/*.xaml
                         включаются в сборку и определяется символ PRO_MODULES
```

- ПРО-код компилируется **в ту же сборку** (а не загружается плагином): так работают
  `partial`-классы окон, single-file публикация и обе платформы без изменений.
- Точка подключения — `static partial void RegisterProModules(IServiceCollection)`
  в `AppServices`: без приватного репозитория у метода нет реализации, и компилятор
  удаляет вызов.
- Пункты меню с `RequiredFeature` **видны всегда**. Public core идёт без отметки; 2.x
  без ключа помечается « · ПРО», получает подсказку «требуется ключ» и вместо действия
  открывает окно «Лицензия» (единый гейт `UtilitiesMenuCatalog.ExecuteExternalGated` /
  `ProGate.Ensure`, без двойного окна). В публичной сборке 2.x — placeholder-пункты
  «только в официальной сборке», которые не вызывают `External`-действие.
- Проверка в коде: `EditionService.Current.Has(ProFeature.Pipelines)`.

### Сборка

**Основная программа всегда собирается с модулями ПРО** — они вкомпилированы в бинарь,
а доступ закрывает лицензия. Публичная редакция (без модулей) — только явный опт-ин.

- Рядом должен лежать клон приватного `Workspace1C.Pro`. `csproj` ищет его сам:
  `..\..\Workspace1C.Pro\src` (репозитории-соседи в одной рабочей папке, например
  `G:\h\Workspace1C\Workspace1C` + `G:\h\Workspace1C\Workspace1C.Pro`) или
  `..\Workspace1C.Pro\src`. Явный путь — переменная окружения `ProSourceDir` или
  `-p:ProSourceDir=<путь к src\>` (завершающий разделитель необязателен).
  Найденный `ProModules.cs` включает `PRO_MODULES`; отсутствие клона даёт
  `HasProModules=false` — это проверяемое свойство, его печатают скрипты и CI.
- Оба скрипта сборки проверяют `HasProModules` **до** `dotnet publish` и падают
  с понятным сообщением и кодом 1, если модулей нет: основная программа так не
  выпускается. Публичная редакция — только явный опт-ин (`-AllowCommunity`
  в PowerShell, `ALLOW_COMMUNITY=1` в bash): скрипт передаёт
  `-p:CommunityEdition=true`, поэтому модули ПРО не включаются, даже если клон
  найден, а в журнал пишется предупреждение.
- После публикации редакция проверяется по самому бинарю:
  `--license-info --json` → `"proModules": true`. Windows-скрипт делает это всегда;
  Linux-скрипт — когда бинарь запускается в текущем окружении (в CI Linux-джобе
  запускается всегда), иначе выводит предупреждение с ожидаемым `HasProModules`.
- Сборка и проверка:

  ```powershell
  cd Workspace1C
  $env:ProSourceDir = 'G:\h\Workspace1C\Workspace1C.Pro\src\'   # только для нестандартной раскладки
  .\build-windows-single-file.ps1 -Configuration Release
  .\dist\win-x64\Workspace1C.exe --license-info --json           # ожидается "proModules": true
  ```

  Без модулей скрипт **завершается ошибкой** (основная программа так не выпускается).
  Публичная редакция — только явно: `-AllowCommunity` (Linux: `ALLOW_COMMUNITY=1`),
  в ней модулей ПРО нет даже при наличии клона (`CommunityEdition=true`).
  Подтверждение — строка «Модули ПРО: найдены (PRO_MODULES)» в журнале сборки и
  `proModules=true` в `--license-info`.
- В GitHub Actions: шаг checkout приватного репозитория с секретом `PRO_REPO_TOKEN`
  (fine-grained PAT с правом чтения `Workspace1C.Pro`). Без секрета релизный workflow
  **падает** для любого запуска. В обеих джобах перед сборкой печатается редакция
  (`dotnet msbuild -getProperty:HasProModules`), после сборки job проверяет
  `--license-info` → `proModules=true`. При push тега `pro_ref` пуст — ПРО берётся
  из ветки по умолчанию приватного репозитория; воспроизводимая сборка — через
  `workflow_dispatch` с полным SHA в `pro_ref`. Пошаговая настройка токена и секрета —
  [`RELEASE-SETUP.md`](RELEASE-SETUP.md).
- Активация: ключ выпускается `LicenseIssuer issue --machine <код> --owner "<владелец>"`
  (по умолчанию `--major 1` для 1.x). После активации функции 2.x доступны сразу,
  без перезапуска: меню пересобирается по `EditionService.Changed`.

## 6. Риски и честные ограничения

- .NET-сборку можно декомпилировать и пропатчить проверку. Это задерживает, но не
  исключает взлом. При необходимости позже — обфускация ПРО-части.
- Код компьютера меняется при переустановке ОС и клонировании виртуальных машин —
  нужен простой порядок бесплатного перевыпуска.
- README, PRO-EDITION и инструкция [`HOW-TO-BUY-PRO.md`](HOW-TO-BUY-PRO.md) приведены
  к политике 1.0.1.120: public core в 1.x бесплатен, новые 2.x-функции — по ключу
  `major=1` в официальной сборке. Версии до 1.0.1.119 не переделываются.
- Внешние участники (PR от 7OH и др.) вносили код под MIT — использовать его в
  платной сборке MIT разрешает; уведомление MIT нужно сохранить.
